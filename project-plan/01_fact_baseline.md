## 二、10 主张审计（降级为待验证假设）

> 每主张按：对照基线 / Golden Set / 正例反例 / 可计算指标 / 失败条件 / 弃权机制 / 回退方案 / 人工裁决点 逐项审计。
> 总体结论：10 主张均缺对照基线与 Golden Set，无操作化失败阈值与弃权机制，全部降级为待验证假设。

### A1. 稳定产出顶刊｜来源 v1.0 §1/§2
- **对照基线**：无。缺历史运行数据证明"稳定"（多次产出均达顶刊录用线）。
- **Golden Set**：未定义。无已发表顶刊论文集作为成功基线。
- **正例反例**：正例=系统产出论文被顶刊录用；反例=被拒或审稿指出系统性缺陷。当前 0 实例。
- **可计算指标**：接收率、审稿轮次、审稿负面评价数。但无基线无法判"稳定"。
- **失败条件**：未定义。连续 N 篇被拒的 N 阈值、审稿系统性缺陷分类均缺。
- **弃权机制**：无。系统何时承认"无法稳定产出"无阈值。
- **回退方案**：无。降级为"辅助草稿工具"的路径未定义。
- **人工裁决点**：投稿(E2)是人裁决，但"顶刊级"判断无客观闸门，依赖外部审稿（非系统可控）。
- **建议动作**：将"稳定产出顶刊"改为"产出具备顶刊投稿要素(可证伪claim+真实引文+可复现包)的工作流"，"稳定"待端到端验证(P5)后以 Golden Set 量化。

### A2. 外部信号充要（防崩盘）｜来源 v1.0 §4
- **对照基线**：无对照实验（有外部信号 vs 无外部信号的崩盘率对比）。
- **Golden Set**：无"仅外部信号防崩盘"的已证明案例集。
- **可计算指标**："崩盘"未操作化（错误累积率？引文幻觉率？方向漂移率？）。
- **失败条件**：外部信号存在仍崩盘（如 L0 白名单过期/复现环境脏/外部源本身被污染）即反证"充要"。
- **弃权机制**：无。
- **回退方案**：无。
- **人工裁决点**：L4 抽样审计（异质）是人裁决，但"充要"是数学断言，需形式化证明或大量对照实验。
- **建议动作**：将"充要"降级为"必要"（外部信号是必要条件），"充分性"留待 P5 端到端验证，并定义"崩盘"操作化指标（如引文幻觉率阈值）。

### A3. 多 agent 投票必提高正确率｜来源 v1.0 §4 A 机制
- **对照基线**：无（单 agent vs 多 agent 投票正确率对比）。
- **Golden Set**：无标注 claim 集验证投票输出与人一致。
- **可计算指标**：投票一致性率、与黄金标准一致率。但无黄金标准。
- **失败条件**：异质模型同质幻觉（都错）→ 投票不提高；judge 与 red-team 同源 → 串谋。
- **弃权机制**：无阈值（多少轮投票不一致就弃权？）。
- **回退方案**：无。
- **人工裁决点**：judge 投票结果可作 Agent 建议 + 人工抽查，但"必提高"无保证。
- **建议动作**：删除"必"字，改为"多 agent 投票可能提高正确率"，配 Golden Set（人工标注 claim 集）量化验证，定义投票不一致时的弃权阈值。

### A4. v4-flash 与 v4-pro 异质｜来源 v1.0 §4 + v1.1 §0
- **对照基线**：异质性应跨族（Claude/GPT/DeepSeek）。flash/pro 同族（同训练数据/同偏见/同幻觉模式）。
- **Golden Set**：无错误相关性度量集。
- **可计算指标**：两模型输出相关性、错误相关性。高相关 = 非异质。
- **失败条件**：flash 与 pro 给出相同幻觉 → 非异质 → 对抗失效。
- **弃权机制**：无。
- **回退方案**：引入跨族模型，但用户限定 DeepSeek 网关（D8）。
- **人工裁决点**：对抗失效时需人判断是否引入外部模型。
- **建议动作**：承认同族局限，异质性靠"异质 prompt（不同角色/流派 red-team）+ 外部锚（L0）"补强，非靠模型族差异。文档将"异质模型族"改为"差异化模型配置 + 异质 prompt"。

### A5. 仅两处人工介入｜来源 v1.0 §10.2
- **对照基线**：recon engine 证实 humanGate=true 仅 E2，domain-direction 为 pre-condition（S13）。源码层"硬介入=2"成立。
- **Golden Set**：但 v1.0 §5 多步"边界(AI 不能)"列暗示更多软介入（步骤 2 claim 构造边界、5 方法推导边界、6 数据标签对齐、9 三合一最重认知决策、13 方法章灵魂叙述）。
- **可计算指标**：实际运行中调用人工裁决的次数（硬 + 软）。
- **失败条件**：系统频繁卡在闸门需人解锁 → 实际介入远超 2 处。
- **弃权机制**：无。
- **回退方案**：无。
- **人工裁决点**：区分"硬必经（2 处：定领域 + 投稿）"与"软抽查/审批（多步）"。
- **建议动作**：文档明确"硬介入 = 2（定领域词 + 按投稿键）"，其余为"Agent 执行 + 人抽查/审批"的软介入，避免"仅 2 处"被误读为"全程无人"。

### A6. 16 步直铺优于闭环｜来源 v1.1 §0
- **对照基线**：无"垂直切片闭环"作为对照证明直铺更优。
- **Golden Set**：无。
- **可计算指标**：端到端成功率、调试成本、返工率。
- **失败条件**：直铺导致多步联调失败难定位 → 直铺不优于闭环。
- **弃权机制**：无。
- **回退方案**：v1.1 有 P1-P6 分阶段交付，部分缓解（但运行时仍全铺）。
- **人工裁决点**：P5 端到端验证为人对照审计。
- **建议动作**：澄清"直铺"指运行时 16 步全流程铺开（非开发期跳过验证）。开发期仍用 P1-P6 分阶段。运行时每步 gate（recon StepStatus blocked/failed/gated）即增量验证点，非二元对立。详见冲突裁决 1。

### A7. L0 白名单 = 真实性｜来源 v1.0 §6.4/6.5
- **对照基线**：白名单 = 质量层级（中科院分区/CCF），≠ 真实性（文献是否真实存在、是否支持 claim）。
- **Golden Set**：无白名单与实际科研质量对照集。
- **可计算指标**：白名单命中率、误判率（真文献被排除 / 水刊被纳入）。
- **失败条件**：重要预印本/新刊被 L0 排除 → 系统无法引用前沿；白名单过期含已堕落刊 → 水刊污染。
- **弃权机制**：无白名单更新机制。
- **回退方案**：无。
- **人工裁决点**：L0 过滤边界判断（新刊/预印本是否放行）需人定。
- **建议动作**：将"L0 = 真实性"拆为两层：L0 管"质量层级"，DOI/原文核验管"真实性"。L0 不能替代引文内容核验。详见冲突裁决 4/5。

### A8. DOI 门禁 = 引用正确｜来源 v1.0 §6.5
- **对照基线**：DOI 存在性检查 vs 实际内容支持性检查。
- **Golden Set**：无标注集验证"DOI 通过 = claim 被支持"。
- **可计算指标**：DOI 验证通过率（但 DOI 通过 ≠ 引用正确）。
- **失败条件**：AI 引用真实 DOI 但 claim 与原文不符 → DOI 门禁通过但引用错误。
- **弃权机制**：无（只查 DOI 不查内容）。
- **回退方案**：无。
- **人工裁决点**：内容支持性判断需人/专项 agent 访问原文。
- **建议动作**：扩展引文核验为完整身份链（claim_id→citation_id→原文证据→定位→核验方式→结论），DOI 存在性只是链首。详见冲突裁决 5。

### A9. agent 自评投票成立｜来源 v1.0 §4 vs §10.4
- **对照基线**：v1.0 §10.4 自述"偷懒用单 AI 自评代替三件套，系统退化为空心论文"——但多 agent 投票若同源仍是变相自评。
- **Golden Set**：无 AI 投票 vs 人类专家裁决一致性集。
- **可计算指标**：投票与人裁决一致率。
- **失败条件**：多 agent 投票与人裁决系统性偏差。
- **弃权机制**：无。
- **回退方案**：无。
- **人工裁决点**：关键 claim 成立性（步骤 9 三合一）v1.0 §5 自述"不可外包给单 AI 自评"——需人领域锚。
- **建议动作**：区分"多 agent 投票"与"单 AI 自评"。投票需异质（跨族或异质 prompt），且关键认知判断（步骤 9）保留人领域锚，不可纯投票裁决。

### A10. 干净复现 = 正确｜来源 v1.0 §11 终极闸门
- **对照基线**：复现结果 vs 独立第三方复现结果。
- **Golden Set**：无独立第三方复现对照。
- **可计算指标**：复现数值一致性。
- **失败条件**：复现成功但方法本身错误（基线太弱/评测有漏洞/过拟合下亦可复现）。
- **弃权机制**：无。
- **回退方案**：无。
- **人工裁决点**：复现成功 ≠ 结论正确，需人审"基线是否值得打败 + 评测是否有漏洞"。
- **建议动作**：将"干净复现"定位为"可复现性"闸门（必要非充分），叠加"敌意审稿能力评测"（外部锚：在冻结审稿缺陷集上评测审稿 agent 的 P0/P1 召回率/无依据质疑率/误报率/证据定位完整率/弃权准确性）+ 人审基线合理性，三者合才近充分。【v1.1 更正：T38 由"追问 claim"改"敌意审稿能力评测"】

## 三、6 冲突裁决建议

### 冲突 1：16 步直铺 vs 增量验证
- **冲突点**：v1.1 §0「完整 16 步，不做垂直切片」(D3) vs v1.0 §7 P1-P6 分阶段增量验证路线。
- **源码旁证**：recon engine（S13/S14）16 步状态机每步有 `gate: TrinityComponent[]`，须 gate 全 pass 才能 exit；StepStatus 含 `blocked/failed/gated` 可回退。即 16 步内部已有增量验证点，非"直铺无验证"。
- **裁决建议**：「直铺」指运行时 16 步全流程铺开（端到端可达），非开发期跳过验证。开发期仍用 P1-P6 分阶段交付。运行时每步 gate 即增量验证点，gate 不达标可回退重跑。两者非二元对立——16 步状态机 = 全流程 + 内置增量 gate。
- **建议动作**：文档澄清"直铺 ≠ 无验证"，明确每步 gate 是增量验证节点；P5 端到端验证作为整体回退机制。

### 冲突 2：人工介入点（输出判断权矩阵）
- **冲突点**：v1.0 §10.2「仅定领域词 + 按投稿键两处」vs v1.0 §5 多步"边界(AI 不能)"列（步骤 2/5/6/9/13 等）。
- **裁决建议**：用输出判断权矩阵区分硬介入与软介入：

| 权属类别 | 定义 | 示例步骤 | 介入形式 |
|---|---|---|---|
| 全自动 | Agent + 闸门可客观裁决 | A2 claim 可证伪性(C)、D3 引文 DOI 核实、6.1 绘图矢量校验 | 无需人 |
| 外部证据裁决 | L0/复现/DOI 等外部真值裁决 | A1 版图扫描(B)、B3 baseline(B)、C1 MVP(C) | 无需人，依赖外部源 |
| Agent 建议 + 人审批 | Agent 出方案，人审否决 | A4 选刊战略、E2 投稿策略 | 人定方向/按键 |
| Agent 执行 + 人抽查 | Agent 执行，人抽样审计 | B1 方法推导、C2 三合一循环、D3 写作 | 人抽样，非每步 |
| 必须人工决策 | 人提供历史数据外信号 | A0 定领域词(价值锚)、E2 按投稿键(物理责任) | 硬必经 |
| 当前无法可靠完成 | 标注需人兜底 | C2 三合一(全文最重认知决策，v1.0 §5 自述"不可外包单 AI")、6.3 技术路线图方法主线理解 | 人兜底 |

- **建议动作**：文档明确"硬必经 = 2（定领域词 + 按投稿键）"对应 recon humanGate=true 仅 E2 + domain-direction pre-condition；其余为软介入（抽查/审批）。避免"仅 2 处"被误读为"全程无人"。

### 冲突 3：异质模型降级表述
- **冲突点**：v1.0 §4「异质模型族（不同族 LLM 交叉）」vs v1.1 §0 限定 DeepSeek 网关（flash/pro 同族，D8）。
- **裁决建议**：flash/pro 同族（共享训练数据/偏见/幻觉模式），非真正异质。真正异质需跨族（Claude/GPT/DeepSeek），但用户限定网关。同族对抗的局限需承认。
- **建议动作**：文档将"异质模型族"降级表述为"差异化模型配置（flash 轻量/pro 重量）+ 异质 prompt（不同角色/流派 red-team）+ 外部锚（L0/复现/DOI）"三重补强，承认同族对抗局限，关键认知判断（步骤 9）保留人领域锚。

### 冲突 4：L0 过滤多体系路由
- **冲突点**：v1.1 §0 双领域（交通中科院分区 + 计算机 CCF）vs v1.0 §6.4 单一白名单体系。且科研论文引用类型远不止期刊（会议/标准/报告/数据集/软件/书籍/预印本/经典）。
- **裁决建议**：按文献类型路由不同真实性/质量体系，L0 不能"一刀切分区表"：

| 文献类型 | 真实性/质量体系 | 路由说明 |
|---|---|---|
| 交通期刊 | 中科院分区 | Q1/Q2 通过 |
| 计算机期刊 | CCF 目录（期刊部分） | A/B 通过 |
| 计算机会议 | CCF 目录（会议部分）+ CORE | 会议无 IF，按 CCF/CORE 等级 |
| 交叉 Venue | 多体系并查（中科院 ∪ CCF） | 任一命中通过 |
| 标准 | ISO/IEC/GB 标准号体系 | 非分区，按标准号官方注册 |
| 政府国际组织报告 | WHO/UN/World Bank 官方源 | 非分区，按官方发布源 |
| 数据集 | Zenodo/HuggingFace/UCI | 非分区，按仓库 DOI + 引用 |
| 软件官方仓库 | GitHub/PyPI/npm | 非分区，看 stars/maintained/官方 |
| 书籍 | ISBN + 出版社声誉 | 非分区，按 ISBN + 学术出版社 |
| 预印本 | arXiv/SSRN | 标注"预印本"，可引用但标注未同行评审，不计入白名单刊池 |
| 经典文献 | 被引量 + 年龄阈值 | 经典 ≠ 在白名单刊，按影响力（高被引经典） |

- **建议动作**：L0 设计为多类型路由表，每类型对应独立核验规则；预印本单独标注不入白名单但可引用（明确未评审状态）。

### 冲突 5：引文核验规范身份
- **冲突点**：v1.0 §6.5 仅"DOI 存在 + 白名单刊"（覆盖虚构文献 #1、部分 DOI 题名错配 #2），缺完整核验链。
- **裁决建议**：标准化引文核验身份链：
  `claim_id → citation_id → 原文证据 → 页码/章节/表/图定位 → 核验方式 → 核验结论`
  - claim_id：此引用支持哪条 claim
  - citation_id：稳定标识（DOI/arXiv ID/ISBN/标准号）
  - 原文证据：引用支持的原文片段（须访问原文，非仅摘要）
  - 定位：页码/章节/表/图精确位置
  - 核验方式：自动（Crossref/OpenAlex 元数据）+ 人工/专项 agent（原文访问）
  - 核验结论：支持 / 部分支持 / 不支持 / 无法核实
- **最高级问题（必须拦截，按严重度）**：
  1. **虚构文献**：DOI 不存在（citation_id 无法解析）
  2. **DOI 题名错配**：DOI 存在但题名不符（AI 拼凑 DOI）
  3. **不支持 claim**：原文存在但不支持所述 claim（最隐蔽，需访问原文）
  4. **撤稿**：文献已 retraction，DOI 仍存在（须查 retraction 状态）
  5. **相关写成因果**：原文说相关，引用写成因果（语义篡改）
  6. **未访问原文却声称核验**：只查元数据 DOI 却声称"已核实"（最高级诚信问题，系统级红线）
- **建议动作**：research_citation_verify tool 实现完整链，#6（未访问原文却声称核验）设为系统级红线——任何 agent 不得在未访问原文情况下声称"已核验"。

### 冲突 6：dsh-research-core 职责过载
- **冲突点**：v1.1 §5.1 dsh-research-core 承担 host + 16 步状态机 + 判断三件套 + L0 + 引文闸门 + 1121 辅助服务，单包职责过载，违反单一职责。
- **源码旁证**：recon engine（S13）已实现纯逻辑分离（engine/ 纯逻辑 + types.ts 头注"P1.6 用 Cordis 包裹"），证明拆分可行。
- **裁决建议**：拆分为：

| 层 | 职责 | 形态 | 证据 |

| 纯领域核心 | 16 步状态机 + Trinity gate 定义 + 引文核验逻辑（纯函数，可单测） | 纯 TS，不碰 Cordis | recon engine/ 已实现 |
