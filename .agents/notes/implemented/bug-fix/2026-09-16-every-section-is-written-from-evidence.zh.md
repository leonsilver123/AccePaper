# Agent Note: Every section is written from evidence, and one with none is refused

Status: implemented

[English](2026-09-16-every-section-is-written-from-evidence.md) | 中文

## Problem

`D3-writing` 交给模型的上下文是:

```ts
{ field, direction, sectionId, claimRef, figureCount, citable }
```

`citable` 是一张图表编号清单 —— "Figure 1"、"Table 1" —— 不是它们背后的数据。所以这个请求带了五个字段,其中没有一个是证据。运行里握着方法规范、测量结果、图表计划与文献记录,一样都没有到达写作者。

于是一个忠实的模型被要求写一节 Results,而它从未被展示过结果。挡在它与一个编造的数字之间的,只有模型自己的克制 —— 而一个拒绝写作的模型,是没完成指令的模型,不是被流水线保护住的模型。

同一个缺口的另一半,是运行在没有东西时做了什么。`bodyTextFor` 从运行自己的数字生成确定性句子,而它**说了**自己是 fixture:`proseSource: 'fixture'` 加一条注记。那对**句子**是诚实的,对**文档**不是。一份方法一节由兜底生成的稿子,读起来与论文一模一样,而读者分不出哪些节是从运行写出来的、哪些是补进去的。

## Decision

`runner/section-evidence.ts` 把一个 section id 映射到该节写作所依据的运行数据,以及它**不能**在没有的情况下写出的证据。`D3-writing` 把前者放进写作者请求的 `evidence`,并拒绝写后者不满足的节。

证据是具体的,因为一坨通用的东西等于让写作者自己挑。Results 节收到数字、单位、以及产出它们的规则版本。Method 节收到实现,**外加**一条 `execution`,把方法声明的版本与结果的版本比对 —— 同一次运行里两个工件具名不同的版本,就是一篇方法一节描述着没产出它数字的那段代码的稿子;这个比对需要**两半**都存在,所以一个不具名版本的方法规范会让该条缺失、该节被拒,而不是拿"无"去做比对。Experiments 节收到运行口径(`runs: 1`、`repeated: false`、`deterministic: true`、`fieldData: false`)—— 那是读者判断这些数字所需要的东西,而此前没有任何一节陈述过它。Discussion 节收到复核过的来源,包括评审者判定 `does_not_support` 的那些 —— 一条到不了写作者的反向来源,与一条到不了门禁的反向来源是同一个缺陷。

必需证据缺失的节**根本不写**。模型不写,`bodyTextFor` 也不补:正文留空,draft 把该节记进 `refusedSections`、把缺失的名字记进 `sectionEvidence`,洞是看得见的。

**运行真正撞上的是 E1。** `assembleManuscript` 本来就拒绝空正文的节(`DSH_MANUSCRIPT_EMPTY_SECTION`)—— 一条比这次改动更老的守卫,而此前从来没有任何东西产出过一节让它去接。于是一个被拒绝的节会传播出去:D3 拒绝它,E1 拒绝格式化含有它的手稿,运行带着具名理由停下,没有任何包被导出。`readinessOfRun` 加的同一道检查是**第二条防线**,不是机制本身。

## Alternatives considered

**把整次运行交给写作者,让它自己挑。** 拒绝。请求是这条流水线决定"一节可以断言什么"的唯一地方,而一个装了一切的上下文,就是一个什么都没被执行的上下文:一个从 Keynote 一节引用那条只有摘要可读的来源的模型,事后是查不出来的。

**没有证据的节继续用 `bodyTextFor` 兜底,并标注它。** 拒绝,而这正是这次改动真正在决定的事。标注是存在的 —— 工件写着 `proseSource: 'fixture'` —— 而一段被标注过的兜底正文,读起来仍然是一篇完成的论文。这条流水线的前提是"看起来可信的主张"就是危险,而"看起来可信的一节"是低一层级的同一种危险。

**任何一节缺证据就让 D3 这一步失败。** 拒绝:那会丢掉所有本来写得出来的节,而运行也就什么都不报告了 —— 它不会说清是哪一节没有证据。记下拒绝继续走,才让 E1 能具名那个洞,也让人能去补那块缺失的证据。

**要求每一节列出它可能会用的一切。** 拒绝:一个会因为缺一样边角料而拒绝自己的节,是一条没人会跑的流水线,而不跑的流水线什么都不执行。每一条只列"没有它,该节就只能断言运行并不持有的东西"的那些证据。

**把证据写进指令的散文里,而不是放进上下文。** 拒绝,理由与当初把图表编号同时放进两处一样:一个要从句子里被模型还原出来的值,是它可以弄错的值,而上下文是测试能断言的东西。

## Consequences

- `packages/research` **1715 passed / 96 files**;`tsc -b tsconfig.host.json` 干净。
- **`tests/section-evidence.spec.ts`(14 条)端到端地证伪了这次拒绝**:一次成功但什么也没找到的检索会留下空的 `references` 节,而测试把这次运行驱动过 D3 与 E1,断言整条链 —— `refusedSections: ['references']`、正文为空、E1 的 outcome 上带 `DSH_MANUSCRIPT_EMPTY_SECTION`、没有手稿工件、readiness 答"不就绪"。空检索是把一节饿死的唯一可达途径,而它是一个真实状态,不是造出来的。
- `D3-writing` 现在声明 `method-spec` 为输入。依赖闭包那条 spec 在任何测试断言它之前就找出了这次读取 —— 那是这条 spec 第二次抓到真实的未声明读取。
- **写作者的上下文现在是可断言的。** 旧上下文里没有任何东西是测试能拿去和运行比对的;新的可以逐节与它来自的工件比对。
- **模型那条路在这里没有被端到端跑过。** 拒绝与供给被跑了,请求的内容没有:本套件里被驱动的运行没有写作者,所以 `D3` 走的是 fixture 路径。两条路径下请求的 `evidence` 字段都由同一个函数构建,这是"两者不可能分叉"的**论证** —— 是论证,不是测试。
- **`sectionEvidence` 记的是供给的证据**键**,不是值。** draft 记的是 `supplied: ['result', 'figures']`,不是那些数字。一个想把句子与它引用的数字比对的读者,仍然要顺着 `resultRef` 找到那条记录。
