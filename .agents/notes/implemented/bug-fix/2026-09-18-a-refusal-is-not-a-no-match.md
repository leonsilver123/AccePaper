# Agent Note: A refusal is reported, and an empty corpus is not a landscape

Status: implemented

English | [中文](2026-09-18-a-refusal-is-not-a-no-match.zh.md)

## Problem

A run stopped at `D3-writing` and the product could not say why. The stage badge read 受阻, the run's next-action selector had no state for a refusal and therefore reported the run as still working, and the actual reason — a `references` section the outline declares, which the drafting step left empty — lived in a gate verdict that no page displayed. Reconstructing the cause took the run's own snapshot, a live query against the same catalogue with the same topic string (1639 matches, whose top 25 all carried DOIs), and reading four files. The record could not answer the question on its own, because two facts it needed to keep apart arrived as one value: *the catalogue answered and matched nothing* and *the catalogue answered with matches that the adapter's filters dropped* were both `outcome: ok, hitCount: 0, hits: []`.

Reading the retrieval path while reconstructing it turned up the same collapse in four more places. A work the catalogue holds without a DOI was dropped by the OpenAlex adapter, so *this adapter cannot name it externally* reached the pipeline as *no such literature*, even though the shared citation contract had been widened to `isbn`, `standard` and `unknown` on 2026-09-18 and only the Zotero channel implemented the widening. A `200` whose body is not a results envelope — a proxy rewrite, a rate-limit notice, a schema change — was read as a genuine no-match, in an adapter whose own class documentation promises it never reports an outage as no-match. The landscape artifact dropped the tool's `truncated` flag. And the A1 step enforced its own stated doctrine — "a landscape built from no records is a fabricated one, so the step fails instead" — for an outage only, so a live corpus that answered and matched nothing passed A1 and surfaced five steps later as a blocked writing step whose stated reason was a missing bibliography. The Zotero channel's topic filter had a defect of its own: it required every topic word of more than three characters to appear as a raw substring of the title or abstract, so the topic `Robustness of platoons to mixed-traffic disturbances` could not match a paper titled "Robust platoon control in mixed traffic flow", and a collection that held it read as empty.

## Decision

- **A topic word matches a title word it opens.** `matchesTopic` now accepts `haystack.includes(word) || tokens.some(token => token.length >= 4 && word.startsWith(token))`, keeping the deliberate AND over the topic's content words and keeping the substring half, which is what lets the topic word `take-over` answer a title that states `takeover`. The rule only ever adds a match. It is still a keyword filter and says so: there is no stemming, the direction is one way (`analysis` does not find `analyses`), and the four-character floor admits `plan` as a mention of `platoons`.
- **A work without a DOI is a hit, not a casualty.** `toHit` skips a record only when it has no id or no title. A DOI-less work is emitted with `ref: { kind: 'unknown', id: <the OpenAlex work id>, title, authors }`, which is the identity the source's own registry minted for it — the ordering and the reasoning `refOf` in the Zotero adapter already states for a collection item.
- **A `200` that is not a results envelope is an outage.** `search()` requires an object carrying a `results` array and a `meta` object, and otherwise resolves `unavailable` with a detail naming what arrived (`arrivedAs` reports a proxy error object by its keys, an array, or a scalar). `{ meta: { count: 0 }, results: [] }` stays `ok` with zero hits, which is the distinction the change exists for.
- **The landscape artifact carries the pre-cap flag.** `a1Executor` records the tool artifact's `truncated` on `landscape-map`, so a run's record distinguishes an answered zero-match from an answered set the filters emptied.
- **A live corpus that matched nothing fails A1.** After the existing `unavailable` refusal, `a1Executor` throws when `liveCorpus && artifact.hits.length === 0`. The message names the topic and states that this is not an outage, because the remedies differ: an outage is the network, and this is the topic or the corpus the deployment names.

## Alternatives considered

- **Let an empty live corpus reach `D3-writing` and stop there, as it did.** Refused: that is what made the incident undiagnosable. The refusal that stopped the run was about a bibliography, which is a consequence; the cause — this topic matched nothing in the corpus this deployment names — was in no artifact, and the run's own record could not distinguish it from a filtered-to-empty answer. A step whose whole product is a landscape must not pass while carrying no records, which is what the step's own comment already said for outages.
- **Report a `200` without a results envelope as `ok` with zero hits and let the adapter's filters be blamed.** Refused: nothing in such a body states what the catalogue holds, so `ok` asserts a fact the response does not carry, and the pipeline acts on it by writing a manuscript whose bibliography is empty. The adapter's class documentation already promised the opposite for every other failure path.
- **Keep requiring a DOI in the OpenAlex adapter and treat the widened contract as Zotero-only.** Refused: the union `LiteratureRefKind` is shared by both channels, so the two would answer the same question differently, and the `unknown` kind would be unreachable on the channel that reaches the open catalogue — the one place books, standards and reports without DOIs are most likely to appear.
- **Add the catalogue's pre-cap `total` to the tool artifact as well.** Refused: `truncated` is derived from that total, so it already carries the zero-match-versus-filtered-out distinction; adding the raw count would change the frozen tool artifact, both of `buildArtifact`'s branches, and the tool's own artifact assertions for no additional bit of meaning. Recorded as a deliberate omission rather than an oversight.
- **Relax the topic filter's AND to OR.** Refused: the AND is deliberate and documented — matching any word returns a whole collection for a topic phrased as a sentence — and the defect was the raw substring test, not the conjunction.

## Consequences

- **An empty live corpus now stops a run at A1, and the end-to-end scenario that used to exercise the D3 refusal is unreachable through the driver.** The machinery that refuses a manuscript with an empty section is still reachable — a corpus that answers with records still leaves a section the drafting step cannot fill — and the rule keeps its direct unit coverage in `manuscript-review.spec.ts`; the case that drove it end to end through the driver is now the A1 case instead. That is the cost of failing earlier, and it is stated rather than absorbed.
- **`truncated` is only as good as each channel's `total`.** The OpenAlex channel reports the catalogue's pre-cap match count; the Zotero channel reports its own post-topic-filter match count, so a collection whose filter dropped every item still reports `total: 0, truncated: false`. The distinction the artifact gained is exact on one channel and weaker on the other.
- **A refusal now fails a run in a place the product must render.** A1 failing is a step with an execution error and no artifact, which is a state the stage view and the run list already show; the panel that reports it is the same one that reports every other step.
- **No gate, threshold or evidence profile moved.** Every change either reports a state the pipeline previously reported as a different one, or recovers a record the catalogue held and the adapter discarded. A run that passed before this change passes after it, and the retrieval returns more rather than less.
