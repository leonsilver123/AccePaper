# Agent Note: Seven pattern sweeps, and the two producers nothing could read

Status: implemented

English | [中文](2026-09-20-seven-patterns-and-what-a-sweep-found.zh.md)

## Problem

Seven defects were fixed one at a time in the research layer on 2026-09-19/20, each invisible to a green suite. Each is a PATTERN, and repairing an instance does not remove the class. This note records what a sweep for the other instances found. Two of the seven turned out to have a live second instance each, and the sweep found two more defects that were not in the list at all.

**The rule "which producers may appear in a snapshot" was stated twice, and the copy that mattered was incomplete.** `run-persistence.ts` refused any `registry.*.producerStepId` that was not one of the sixteen steps, with a hard-coded exception for `ACCEPTANCE_PRODUCER`. That exception had been added after an accepted manuscript made a snapshot unreadable — `listRuns` threw, the picker came back empty. The fix covered the ONE producer core writes. It did not cover the two the TEAM writes: `manuscript-import` and `materialize-manuscript`, both published through `publishArtifactVersion`. Measured through the service: after a hand-edited file is imported, `persistRun` rejects the snapshot, the run's save never lands, and the next approval comes back `research/approval-save-failed` — the round trip the whole unit exists for failing at its last step. The document was durable only until the next `tryLoad`.

**The journal-rule decision was implemented twice, and the two copies disagreed.** `checkVenueRules` was corrected on 2026-09-18 to the profile's three findings — read and stated, read and NOT stated, and never read — so that only the last blocks a submission. `journalRulesOf` in `final-package.ts` kept the older two-state reading (`verification !== 'verified'`) and re-derived the counts itself, while its own JSDoc said `checkVenueRules` "is the decision, taken where the profile lives rather than re-derived here". The shipped `TRC_PROFILE` carries one `not_specified` rule (`graphical-abstract`), so `journal-rules-verified` refused EVERY submission of a paper written for that journal: measured, `1 of 9 requirement(s) ... have not been read (graphical-abstract)` on a guide that had been read in full. Only the WBS-level spec noticed, and it asserted the refusal for a fixture journal whose rules are genuinely unread.

**The repair re-renders the typeset form and does not re-run the gates, and nothing said so.** `materializeManuscript` is the documented answer to a form that fell behind its document. The failure mode was not the one the limitation claimed: a hand edit moves `manuscript`, and `approvalStalenessOf` does refuse the old approval. What nothing covered was the order a page actually uses — edit, repair, THEN approve. Measured end to end: the repaired run reported nothing wrong but its evidence profile and its review policy, and on a production run with a satisfied policy it would have exported as FINAL a document no gate had judged.

**`project-view.ts` reported what a step WOULD run under as what RAN.** `stepProducerOf` had already been introduced so `drive.ts` and the package's run facts read a step's producer off its own artifacts, and `run-summary.md` was fixed with it. The projection the browser renders still took `entry.producer`, the registry's declared brand, and called it `producer` — the same field name for the other question. The panel reported a model-written draft as produced by the table renderer the step executes.

**And the tests that were supposed to catch these could not.** A sweep of the research specs found assertions whose two sides resolve to one value, and cases whose TITLE names an axis the body never varies. Three were certain: `closed-loop.spec.ts` compared a gate verdict's `targetRefs` with the commit receipt core builds them from; `a3-agenda-derivation.spec.ts` compared `agenda.plan` with `agenda.phases`, which the model branch assigns from one array; `convergence.spec.ts` asserted a summary starts with a prefix interpolated from the same field. `researchview-component.dom.spec.ts` was titled "renders all nine tabs" over a hand-written list of nine labels while the workbench had eleven — the revision and quality panels were never rendered under test at all.

## Decision

- **The producer roster is read from the run, not kept in core.** `parseRegistry` now accepts a non-step producer when the run's own audit log holds an `artifact-republished` event naming THAT slug under THAT producer. The alternative — a constant list in `run-persistence.ts` — is the thing that was already wrong: it can only name the producers core knows about, and the ones a deployment adds are the ones that broke. The acceptance's own `manuscript-accepted` event is a different kind, so `ACCEPTANCE_PRODUCER` stays an explicit clause beside it. `parseRunSnapshotPayload` parses the events first and passes them in.
- **The journal decision lives where the rules live.** `journalRulesOf` calls `checkVenueRules` and carries its refusal into `FinalPackageFacts.journalRules`, and the check reports the refusal's own sentence rather than a paraphrase. `established` became `read` — the count of rules somebody read, whether the reading found a requirement or found none stated — and `refusal` is what `passed` reads, because the counts alone cannot express the empty-guide case that `checkVenueRules` refuses.
- **A repaired typeset form is a refusal a caller must resolve.** A sixteenth condition, `manuscript-gated`, fails while the typeset artifact carries the repair's `materializedAt` marker: no gate has judged the document the run holds, and the format step's verdicts stand on the document it replaced. The remedy is in the sentence, because a repair cannot become a passing one — `submitGateVerdict` refuses to re-adjudicate a settled attempt (INV-VERDICT-IMMUTABLE). The document is still exportable as the working draft it is.
- **Two fields, two names.** `StepProjection.producer` is now resolved by `stepProducerOf` over the step's declared outputs, and `StepProjection.declaredProducer` is the registry entry's brand. Read over the declared outputs rather than over the registry's own grouping, because an artifact a person published over is filed under `human-acceptance` and would otherwise drop out of the step whose work it is.
- **A same-value comparison is repaired by finding an independent side, never by deleting the assertion.** The gate verdicts are compared against the REGISTRY, which is what the run holds; `agenda.plan` against the stages the model reply stated; the hash cases against a value the test moved. Where the axis genuinely belonged to another layer, the name was changed to what the body establishes and a pointer added — `counts not_applicable as a reported exemption, with or without the detail` (the parser makes that distinction, and its case is in the same file), and `records the inputs it binds, as the registry held them`.
- **A roster a spec iterates is the component's own.** `ResearchWorkbench.tsx` exports `WORKBENCH_TABS`; the coverage spec reads it instead of keeping a copy, asserts its size, and clicks every entry.

## Alternatives considered

- **Add the two team producers to the constant in `run-persistence.ts`.** Rejected: it is the same fix that already failed once. Core cannot import the team's constants (the dependency runs `core ← team`), so any constant here is a roster core has to be told about, and the next deployment-defined operation reintroduces the defect. The run's own log is the only source that is complete by construction.
- **Keep `journalRulesOf` re-deriving and just change `!==` to `=== 'unknown'`.** Rejected: that makes the two agree today and leaves two implementations of the same judgement. The empty-guide case is the one that shows why — `checkVenueRules` refuses it with an empty `unverified` list, which no re-derived count can express, so the re-derivation would have passed a venue whose guide nobody had looked at.
- **Re-run E1's gates inside `materializeManuscript`.** Rejected: it is an adjudication no attempt records, and the engine refuses it — a settled attempt is never re-submitted. Making the repair's consequence explicit is the honest half that is reachable.
- **Refuse the repair itself, or drop the repair path.** Rejected: the repair is the legitimate answer to `manuscript-typeset`, which is what refuses a form that renders a superseded document. What was missing was the second question, not the first answer.
- **Rename `producer` rather than adding a field.** Rejected: the wire has carried the name since the driver began recording producers, and the value that a reader of a step cares about is what ran. The declared brand is the new name because it is the new question.
- **Rename the overloaded identifiers the sweep found.** Rejected on the constraint the sweep carried: `'draft'` is three things and a blanket rename broke ten assertions once already. Where a meaning was genuinely ambiguous it was made explicit in the JSDoc that reads it.

## Consequences

- A run whose document was imported or re-rendered saves and loads again, and a person can approve it. The refusal a hand-edited run meets is `research/approval-save-failed` no longer.
- The shipped production profile can produce a final package: `journal-rules-verified` holds for a guide that was read in full, including the subject it states nothing about.
- A repaired run is exportable as a draft and refused as the package a journal receives, with the reason stated. `start-run.spec.ts`'s approval case now expects two unmet conditions where it expected three, because the third — the journal's — is the one this change fixed.
- The panel and `run-summary.md` now agree about a step's producer, because both read it from the artifacts; the declared brand is beside it under its own name.
- Five spec files were strengthened rather than pruned. The tests that were tautologies now fail when their subject breaks, which was not true before — each was verified by reverting the fix and watching it fail.
- The verification limit is stated rather than implied: `packages/research/dsh-research-web/tests/package-check-vocabulary.spec.ts` is what forced the client vocabulary entry for `manuscript-gated`, so a new condition reaches the screen named in both languages or not at all. Two statements in `packages/research/dsh-research-team/README.md` — committed in `edc5a636` while this work was in flight, and owned by another writer — are now stale and are left for that writer: the "What is not here" paragraph still says `materializeManuscript` re-renders without re-running E1's gates and that "what a hand edit costs is caught by the approval", which is the state before `manuscript-gated`; and the journal paragraph describes `checkVenueRules` as the decision without saying that `final-package.ts` now reads it rather than counting the rules a second time.
