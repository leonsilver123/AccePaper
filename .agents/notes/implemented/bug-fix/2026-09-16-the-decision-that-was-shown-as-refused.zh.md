# Agent Note: 那次被显示成"被拒绝"的决定

Status: implemented

[English](2026-09-16-the-decision-that-was-shown-as-refused.md) | 中文

## Problem

工作台有两条路会告诉操作者"你的审批失败了",而它其实成功了。

**保存失败被丢掉了。** 后端本来就在决定旁边返回 `persisted`、`persistenceError` 与
`projectionError`,并在自己的注释里写明了理由:"这里的失败**不会**取消任何决定 —— 运行在内存里已经
是新状态了 —— 所以它与决定**并列**报告,而不是被变成一句会错误描述发生了什么的拒绝。" 而客户端的
`readDecision` 只读 `runId`、`stepId`、`attempt`、`status`、`operator` 与 `snapshot`,**别的什么都不
读**。于是一条只存在于服务端内存里的决定 —— 下一次重启就没了 —— 渲染出来与一条落了盘的一模一样,
而操作者要凭一个猜测决定能不能关掉页面。

**一次构建摘要的失败把决定替换掉了。** 决定成功之后,客户端会重建工作台摘要。如果那一步抛错 ——
一段读者解析不了的投影 —— 处理函数会返回 `{ ok: false, code: 'malformed' }`。面板于是显示一次失败,
而后端说这次运行 `passed`;操作者合理的下一步是再按一次"批准",而那最多只会得到 `not-pending`。

## Decision

回执带上决定自己的身份与它的持久性:`approvalEventId`、`decidedAt`、`persisted`,以及两个错误串
(有的话)。面板把三件独立的事实分别说出来,过去它只说一件:

1. 决定是什么、谁做的(不变);
2. **决定已生效,但没有保存**,带后端给的原因(`persisted` 为 false 时);
3. **决定已生效,但页面未能刷新**,带原因(没有摘要时)—— 而那个原因分得清"后端没有投影"
   (`projectionError`)与"客户端读不了后端发来的东西"。

这三个回执字段在 wire 上是**必填**的。省略它们的后端会被报成"客户端与主机不是同一个构建",而不是
被默认填充:默认填充 `persisted` 等于把这个字段存在的唯一理由编出来。

## Alternatives considered

**`persisted` 缺失时默认 false。** 拒绝:那会在一个早于该字段的主机上给每一个操作者都报一次警告。
这个字段的全部用途就是区分两个状态,而一个默认值会静默地替人选一个。

**`persisted` 缺失时默认 true。** 更该拒绝:那会告诉操作者他的决定能活过一次重启,而没有任何东西
确立过这一点。

**摘要失败时报成 `ok: true`,不留别的痕迹。** 拒绝:操作者会看到一个过期的页面,而不知道原因。
这次失败被说出来 —— 在回执**旁边**,而不是**代替**它。

**摘要失败时自动重试决定。** 拒绝:决定已经落地了。一次重试就是第二次决定,而后端最多只会拒绝它。

## Consequences

- `tests/approval-panel.dom.spec.ts` 钉住三件事:一条"被拒但已应用"的决定显示回执**和**未保存警告,
  且**不**显示为失败;一次读不回来的刷新显示回执**和**刷新说明,且不声称决定未保存;一份没有
  `persisted` 的回执被当作构建不匹配拒绝,而不是被默认填充。
- "面板自己不决定任何东西"的既有断言依然成立:一次拒绝让门保持 pending,而只有后端返回的摘要会替换
  屏幕上的东西。
- **这不做的事**:它不让决定变得持久,它让操作者**看得见**它不持久。持久化仍然是主机的职责,而一条
  未保存的批准能否作为最终导出的门禁,是下一个单元要回答的就绪问题。
