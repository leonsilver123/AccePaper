# Agent Note:一次运行研究什么,由模型提出、由人确认

Status: implemented

[English](2026-09-15-a-run-starts-from-a-confirmed-plan.md) | 中文

## 问题

启动一次运行原本就是一次点击,而它会研究什么是运行器源码里的一个常量 —— 按下「运行流水线」,拿到的是八到十五分钟关于一个没人选过的题目的工作,而它将被拿什么判定,只有当手稿出来、或者当一步以"你从没见过的那条主张"为理由弃审的时候才看得到。

在只有一份研究的时候这还忍得下去。方案能带别的东西的那一刻它就不成立了:一次运行的全部价值,恰恰在于人可以在跑之前决定它是关于什么的。

## 决定

**`@Remote('proposeDirections')` 把一个领域变成可确认的候选,客户端的运行控件打开一个对话框,而 `run` 只跑那个人确认过的方案。**

- `runner/direction-proposals.ts` 拥有线格式(带标签的行,与流水线其它散文步骤同一套约定)以及"一个候选能不能端到人面前"那条规则:每个候选都过 `prediction-gate.ts` 的 `claimRejectionOf`,也就是 C 通道自己那条主张级检查。会让运行卡住的主张,带着**门**的理由被拒,而不是端上来再在半路弃审。
- **被测量的量不是模型能选的。** 这次运行只能测它的研究测的东西,所以那个量随请求进去,指令要求预测必须点出它。关于别的量的候选会被绑定检查拒掉。
- **方向是读出来的,不是问出来的。** `commitment.direction` 取自 `shall <word>` 那个位置 —— 那是线格式而不是阅读理解,用的也正是门用来核对它的那个函数。再让模型声明一遍,只会造出一个能与句子矛盾的字段,而候选本来就没有什么声明可以矛盾:声明就是在这里被构造出来的。bound 与 threshold 是问出来的,并且要跟句子对质。
- `requirePlan` 在线的边界上校验方案。下游完全信任方案 —— 手稿标题、A1 的检索题目、C 通道判决的那条主张 —— 所以一个畸形的方案不会"在入口处失败";它会产出一批互相矛盾的工件。用不了的方案**带着理由**被拒,永远不会被默认方案顶替。
- 门的主张级检查现在够得到而无需测量:`evaluatePrediction` 被拆开,由 `claimRejectionOf` 拿住它们,`evaluatePrediction` 调它、然后再去测量。候选没有研究可跑,而为了够到这些检查去伪造一个测量,会让对话框依赖它正想避开的那一半。
- 对话框不为候选编任何句子。它印出的每一行要么是 locale 文案,要么是模型自己的话;判定标准是从方案声明的承诺渲染出来的 —— UI 文案归 locale,而人确认的那个数必须就是运行将被拿去评判的那个数。

## 考虑过的其他方案

**让模型直接给一份 JSON 的 `StudyPlan`。** 按流水线其它散文步骤早就否决 JSON 的同一个理由否决:带标签的字段靠字符串比较就能读,而 JSON 体会因为一个不带含义的标点让整步失败。它还会把"某个字段缺失"变成解析失败,而不是一个有名字的缺口。

**让模型选指标。** 否决,因为那是对"接下来会发生什么"说了假话:运行测的是它研究测的东西,所以一个点了别的量的候选会在这里被接受,然后在每一道闸门上弃审。诚实的版本是指令说明预测必须是关于哪个量的,并由绑定检查执行。

**让模型连承诺的方向一起声明。** 否决:它可以用核对它的同一个函数从句子里推出来,而一个事实两个来源,正是这批改动已经删过两次的缺陷。

**候选请求失败时回落到默认方案。** 否决:那次运行就会是关于一个没被人选过的东西,还标成是他的选择。对话框报告失败并退回填写领域那一步。

**无条件打开对话框,让没有散文通道的部署自己去失败。** 否决:那种部署会根本没有办法启动一次运行。宿主提供不了候选接缝时,运行控件直接跑默认方案,workbench 会说它走的是哪条路。

## 后果

**一次运行的第一件事是一次确认,而页面能被拿去和宿主对质。** DOM spec 直接断言那条承重性质:`onRun` 收到的方案就是对话框展示的那个方案。八个用例覆盖了填领域、确认、从承诺渲染出的判定标准、通道说明、"有拒绝"与"什么都没提"可区分、请求失败不启动任何东西、取消,以及没有候选接缝那条路。

**模型写不出来的候选仍然被报告。** 每个块都被拒的回答,和什么都没提的回答,是两个事实;回答里两张表都带,对话框分别说出来。

**从线上下来的方案现在是一条被校验的边界。** `tests/study-plan.spec.ts` 驱动十条拒绝,其中一条是它自己找出来的:指标键是从方案的 `metric` 对象里用一个只认字符串的读取器读的,于是每一份方案都被拒成"关于 ''"。spec 第一次跑就抓到了。

**浏览器探针失败了两次,两次都是探针自己的问题。** 第一次它报判定标准与候选都不见了;诊断输出显示对话框停在 `正在生成方向…`,因为等待条件是字符串 `判定标准` —— 而对话框自己的说明里就有这句("每个方向都带着它的可证伪预测和判定标准")。它在第一轮就返回了,那时请求还在飞。这正是探针文件头自己点名的失败形态:「探针静默通过」—— 一个读文案而不是读渲染状态的探针。第二次它报五分钟内没有任何运行,而持久化快照显示 16 步全部通过、E2 在第 11 分钟左右被浏览器操作员批准 —— 运行只是比探针的耐心长,而那份耐心比部署自己的 `stepTimeoutMs`(900 秒)还短。两处等待现在都改成 DOM 钩子,预算不短于部署自己的。

**探针第三次跑是 38/39,而那一处失败又是一个过时的断言。** 它把整条链都驱动了:对话框打开、开着的时候什么都没跑、宿主提出了一个门判得了的方向、判定标准渲染出来(`判定标准:the platoon's minimum time-to-collision (s) 应不低于基线 15%`)、确认后运行启动、16 步全部跑完、E2 被浏览器操作员批准、导出里有 11 个文件。那条同一性断言是**精确**通过的 —— `{"proposed":"The platoon's minimum time-to-collision (s) shall rise by at least 15%.", "matchedExactly":true}` —— 这正是本阶段的验收:对话框展示的那句话,就是运行记录的那句话。

失败的是 `the page shows the study's platoon composition`,而它一直是靠 pack 自己的主张**文本**(`the HV-AV-HV platoon shall exceed…`)通过的,而「按人确认的方案跑」的运行不再陈述那句话。它其实是在第二次断言「pack 的主张到了页面上」,而不是「研究的编成被记下来了」;编成在 `experiment.json` 与 `claim-evidence.json` 里,这次运行的导出被手工读过、确实带着它。该断言现在改读导出。**这次改写发生在运行之后,探针没有执行过它** —— 它是这次改动里唯一一处「新形态未被验证」的断言,而写明这一点正是记下它的意义。

**对话框是 workbench 自己渲染的一个模态,而共享的那一个已经存在。** `@deepseek-ai/dsh-client-ui-primitives` 导出 `Modal` —— portal 到 `document.body`、Escape 与遮罩关闭、设计令牌 —— 而 `ui-agent-preset` 的复制对话框就是「两个字段 + `footer` 里一组按钮」那个形态的先例。这个对话框自己搭了一个固定定位的背板,代价是没有 Escape 处理、颜色也不是令牌。换过去是机械的(加 workspace 依赖、替掉背板和 footer),推迟只是因为这次改动要验的行为已经验过了;写在这里而不是留给下一个人重新发现,因为「没有模态原语」会是一个假的推迟理由。
