# Agent Note: 那个说不出自己扔掉了什么的解析器

Status: implemented

[English](2026-09-16-the-parser-that-could-not-say-what-it-threw-away.md) | 中文

## Problem

`D4-rebuttal` 把模型的回复读成 `RevisionIssue`,交给 Issue → Patch → Verify 那条循环。那条循环 的每一条测试都在 TypeScript 里构造 issue,所以循环被覆盖了,而解析器没有 —— 对它的一次离线探针 找到了三个静默的失效模式:

- `PATCH: NONE` 与"根本没有 `PATCH` 行"产出同一个值。应用器把这个值读成"作者回答了这条意见, 没有改正文",于是一份只是没按格式作答的回复被记成 `accepted_explanation`,该步**通过**。 代码旁的注释声称这两者可分辨。它们不可分辨;
- 缺少 `SECTION` 的交换被 `return` 出了累加器。一份三段交换、其中两段畸形的回复产出了**一条** issue,`openIssues` 是空的,而运行里没有任何地方记下这份回复有三分之二被丢掉了;
- `PATCH:` 后面什么都没有,因同一个理由落进了与"没有这一行"相同的分支。

被量出来的每一份回复,都是这个仓库自己写的。解析器做不到的事情是**拒绝**任何东西。

## Decision

解析器自成一个模块(`runner/issue-parse.ts`),而它能说出自己丢掉了什么。

`parseReply` 返回 `{ issues, discarded }`。开了头却没有完成的交换被记进 `discarded`,带着它的 1 起始位置、它的 `CONCERN` 文本、以及它缺哪些标签 —— 于是一个读者能在回复里找到那一段,而一个 计数跟着工件一起走。它分辨三种 patch 状态而不是两种:`replacement`、`declared-none` (`PATCH: NONE`,一个结论,而且是合法的一个)、以及 `missing`(没有 `PATCH` 行 —— **不是**接受)。

`assertWellFormed` 把报告变成拒绝。交换不完整的回复让该步失败,消息里带不完整交换的数量、它们 的位置、以及它们缺的标签;一条 `CONCERN` 都没有的回复同样失败,因为一份没有交换的答辩什么也没 回答。

空值这一情形,正是标签读取器返回 `''` 而不是 `undefined` 的原因:空值算作**被陈述过**且为空, 这就是 `PATCH:` 与"没有 `PATCH` 行"的分野。那个分野是这个值的全部意义,而它现在只在一个地方。

## Alternatives considered

**把解析器留在原地,只给它的返回值加一个 `discarded` 数组。** 拒绝:执行器的职责是把 issue 绑到 它们写作时针对的那个版本上、并写出工件,而"文本 → issues"这一步有自己的契约和自己的失败词汇。 拆分也是"不必驱动一次运行就能测失败"的原因。

**在解析器里遇到第一段畸形交换就抛。** 拒绝:一份三段交换里坏了两段的回复,应该在一句话里把 两段都说出来。该步的下一次尝试能拿到全部信息,而工件在"调用方选择继续"那条路上也保住了计数。

**把缺失的 `PATCH` 读成 `declared-none`,让应用器去判断。** 这是同一个静默默认换了名字。应用器 看不见回复,分不出一个刻意的 `NONE` 与一次遗漏;在那里判断,就是同一个缺陷下移了一层。

**把散文回复解释成交换。** 拒绝,而且值得写下来:一个去猜哪句话是意见的解析器,会在恰恰最要紧的 那些回复上猜错,而每一次猜错都关闭一条 issue。不按格式作答的回复被拒,而该步的失败说清楚期待的是 什么。

## Consequences

- `tests/d4-model-revision.spec.ts` 让 D3 与 D4 穿过一个按各步自己的格式作答的写作者。那份格式 正确的 fixture 就是浏览器运行真实产出的回复 —— 三段交换、三段全部被 patch、三节被修订而四节 没有;畸形的那份少一个 `SECTION`。
- 应用器的测量是**反过来的断言**而不是断言本身:正文**变过**的那些节正是被 patch 的那些,没有 任何一节在没有 diff 的情况下声称 `revised`。两份清单按排序集合比较,因为 `patchedSections` 跟着回复提出意见的顺序,而草稿的各节跟着大纲 —— 按同一个顺序比较,断言的是一个巧合。
- 畸形的回复把该步留在 `in_progress`,带一个具名交换的 `executeError`,运行不产出 `revised-draft`、也不产出 `formatted-manuscript`。下游没有任何东西是拿一份流水线读不懂的回复 建起来的。
- 该步的回复格式现在是一份背后有拒绝的契约。用散文作答的模型让该步失败;它不会被静默记成 "回答过了"。
