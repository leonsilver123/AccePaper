# Agent Note: PDF 被逐页读出来,而且是在真实引擎上

Status: implemented

[English](2026-09-17-the-pdf-is-read-page-by-page.md) | 中文

## 问题

复核的 R01 记下了 PDF 分支当时的行为:它跑 `pandoc -t latex --pdf-engine=…`,把 stdout 按 UTF-8 文本抓下来,写成 `manuscript.pdf`,然后报告成功 —— 退出码 0、没有 `%PDF-`、内容是 LaTeX 源码。这条路径已经修好(pandoc 写 `.tex`、引擎对那个文件运行、按字节读回、校验文件头),而复核为关闭它设的门槛是:必须有真实引擎编译它,并且要看页面。**`%PDF-` 文件头也不是那个门槛** —— 一个开头正确、却只有一页空白页的文件能通过文件头检查。

而且当时根本没有任何东西产出 PDF。本机没有装 LaTeX 引擎,而 E1 只编译 `html` 与 `latex`,所以**即便**部署有引擎,它的工件上也不会记下 PDF。

## 决定

- **本机装了真实的 TeX Live**(来自 CTAN,`scheme-minimal` 加上 `pdftex` 与 pandoc 模板需要的宏包),位于 `.workbuddy/tmp/texlive/tex` —— 这是部署工具链,不是源码:它在仓库跟踪树之外,**没有任何指向它的路径被提交**。引擎由 `DSH_LATEX_ENGINE` 或这个检出本地的安装找到。
- **E1 在部署能产出 PDF 时编译 `pdf`** —— 依据编译器自己探测出的 `formats`,所以没有引擎的机器永远不会被要求一个它会拒绝的 PDF。三种格式渲染自**同一份**文档模型,于是它们不可能描述不同的稿件;把 PDF 排除在外,会让「这个部署有引擎」这件事无法从包里验证。
- **`tests/pdf-acceptance.spec.ts` 把页面读出来。** 它通过这道缝自己的入口(`compileManuscript`)编译一份文档,把返回的 **base64** 字节写盘,校验文件头,然后**按读者读它的方式**读这份文档 —— 用真实解析器(`pypdf`)—— 并断言:
  - 页数大于一,这正是「引擎真的分了页」的意思,而退出码说不出这件事;
  - 第 1 页带着第一节的标题**和**它的正文;
  - 第 1 页**没有**第二节的正文,而后面的某一页有。

  最后这一对,正是「一份真实文档」与「页面全空、或每页都是同一页」之间的区别。夹具长到会分页,因为一页的文档无法证明页面是真实的。
- **它只在装了引擎的机器上运行**(`describe.skipIf`),没有引擎时明确报 skipped:引擎是部署工具链,不是本包的依赖,而被跳过的真实工具用例与通过是**可区分**的。

## 考虑过的其他做法

- **只断言文件头,再从字节流数页数。** 拒绝作为全部检查:数 `/Type /Page` 出现的次数,说明不了页面上有什么,而复核的门槛是文档本身,不是它的结构。
- **用替身引擎。** 复核逐字拒绝,而且拒绝得对:要修的缺陷正是「从一个不是 PDF 的文件报告成功」,替身只会复现它而不是抓住它。
- **等部署配上引擎,先不验证 PDF 路径。** 拒绝:R01 要等真实引擎编译过才能关闭,而「本机没有引擎」是一个环境事实,不是代码的性质。
- **把引擎 vendor 进仓库。** 拒绝:TeX 发行版是部署拥有的工具链,提交它会让仓库背上一棵平台相关的二进制树。

## 后果

- **实测**:pandoc 2.12 → pdfTeX 3.141592653-2.6-1.40.29(TeX Live 2026)→ 一份多页 PDF,上面那些逐页断言全绿。
- **这里没有覆盖的。** 这次验收编译的是一份合成文档;**出货 profile 构建出来的包**还没有被编译成 PDF,因为 profile 没有点名引擎(部署自己加 `latexEngine:`)。PDF 里的图没有被逐页断言 —— 栅格被内联,`compiled-document-complete` 管的是有没有丢图,但「这张图在第 3 页」没有被检查。引擎住在仓库之外,所以这条用例在没装引擎的机器上会跳过。
