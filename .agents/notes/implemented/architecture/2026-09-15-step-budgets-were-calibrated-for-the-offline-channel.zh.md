# Agent Note:每一步的超时是照离线通道定的,所以真模型跑不完一次运行

Status: implemented

[English](2026-09-15-step-budgets-were-calibrated-for-the-offline-channel.md) | 中文

## 问题

这条流水线**可以**被配置成走真模型,而一旦这么配,它跑不完。

每一步的超时在 runner 的注册表里是常量 —— 工具步骤 `REAL_TOOL_TIMEOUT_MS = 5_000`,fixture 步骤 `FIXTURE_TIMEOUT_MS = 2_000`。这些数字配的是部署出货时那条通道:确定性散文路由是**算**出来的,所以一个散文步骤毫秒级返回。

把出货 bundle 切成 `prose: { kind: llm, provider: deepseek-official, model: deepseek-v4-pro }` 后实测:A1-landscape —— 第一个写散文的步骤 —— 被记成 `status: "timeout"`,`durationMs: 5009`,运行再没离开阶段 A。快照里只有一个步骤、状态 `in_progress`,而且**任何地方都没有错误信息**:超时不是失败,所以读者什么也读不到。把预算抬上去之后,16 步里有 12 步原样跑完 —— 这正是"该负责的是这套标定、不是模型路由"的证据。

同一次测量还挖出**同类的第二道天花板**。D3-writing 把**每一节**都放在**一步**里写,一次并发发出每节一个模型调用,最后死在 writer 自己的空闲上限上:`[research-prose] D3-writing: agent loop idle timeout after 120000ms`,`durationMs: 120010`。那个上限覆盖的是**一次**写入,而这一步是同时七次。

两件事合起来,使得 `kind: deterministic` 成了**唯一**能跑完配置 —— 它不是 bundle 里记下的偏好,而是这套常量唯一允许的取值。

## 决定

**两道天花板都变成部署字段,因为正确的预算取决于部署配了哪些通道,而不是取决于步骤。**

- 研究引擎上的 `Config.stepTimeoutMs` 对整次运行覆盖注册表里的逐步值;构造时**拒绝**非正有限数 —— 一个 0 预算在远端读起来就是"运行无缘无故停了"。
- `LlmProseWriterConfig.idleTimeoutMs` 本来就是 `prose` 行上的字段、也本来就透传到位;现在由部署明确写出。

出货 bundle 两个都设(`stepTimeoutMs: 900000`、`idleTimeoutMs: 600000`),并把得出该数值的那次测量写在旁边。

## 考虑过的其他方案

**把常量调大。** 按仓库自己的规则否决:注册表声明的是**每一步**的超时,那是被运行的工具的属性,不是部署的属性。调大离线数值还会让一次运行在毫秒级返回的步骤上白白耗掉五分钟。

**按配置的通道推导预算**(deterministic → 5 秒,llm → 15 分)。作为**隐式默认**否决:部署已经写明它走哪条通道,而仓库的规则是这类选择应当是拥有它的实现里一个显式的 `resolve(request): Spec` 步骤,而不是一个要读者从两个文件里反推的隐藏推导。

**让 D3 逐节发起调用,好让每一次都塞进 120 秒。** 作为本缺陷的修法否决(不过单独做也许值得):它改的是这一步花多久,而不是部署能不能声明自己的预算;而它绕开的那道天花板,任何慢步骤都会撞上。

**把 `DriveOptions.timeoutMs` 继续当作 fault injection,另加一个字段。** 否决:那个字段就是部署的预算,把它读成测试专用,正是让一个部署变量以常量形态活下来的原因。它的文档现在写明它是什么。

## 后果

**一次运行的墙钟时间现在由部署来声明。** 默认值没动,所以离线路由的行为与从前完全一致;配了模型路由的部署必须同时声明预算,bundle 自己的注释里带着"少写一个会得到哪种错误"。

**预算设得太低仍然是静默的。** 超时被记成 `timeout`、步骤留在 `in_progress`,没有任何错误文本到达工件或页面。本文与该字段的 JSDoc 都写明了这一点,因为这种失败形态看起来就是"运行无缘无故停了";把它变响亮是驱动层另一件事。

**散文引用这条路现在被演示出来了。** 走模型路由时,E1 工件的交叉引用报告不再全是未引用:实测 `{"cited":["Figure 1","Figure 2","Table 1","Equation 1","Equation 2","Equation 3"],"uncited":[]}`。离线路由永远产不出这个,这也正是当初引入该报告的那篇 Note 把它记为"在离线路由上无法验证"的原因。
