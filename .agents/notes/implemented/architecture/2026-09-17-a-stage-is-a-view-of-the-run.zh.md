# Agent Note: 阶段是这次运行的一个视图,不是第二台引擎

Status: implemented

[English](2026-09-17-a-stage-is-a-view-of-the-run.md) | 中文

## 问题

工作台按管线词汇组织一项研究:九个以工件与机制命名的标签页(pipeline、gates、adversarial、roadmap),
十六个用 `A1-landscape` 与 `E2-submit` 标识的步骤,以及一套四个部分各有其名的就绪模型
(`evidenceProfile`、`profileEligible`、`submissionReady`、`readinessNote`)。没读过设计文档的研究者能看出
有事情发生了,却说不出自己在看什么、它产出了什么、是不是被挡住了、以及正在被要求做什么。人真正需要的
几种状态 —— 等我的决定、失败了且原因在此、还没轮到且缺什么 —— 散落在四个面板和两套词汇里。

把"第十六个阶段"做成真正持有状态的单元会更糟:同一项运行上跑两台状态机,对"完成"各执一词,而管线自己的
裁断不再是"研究是否推进"的权威。

## 决定

**阶段是**架在这项运行自己的记录之上的分组**,它显示的每一个状态都从那些记录推导。**

- `stages.ts` 列出六组,并为每一组列出它所报告结果的管线步骤。**研究任务与材料**这一组不报告任何步骤:
  研究问题、材料与人确认过的方案不是第十七个被执行的步骤,报告它会声称管线做过它没做过的事。
- **阶段的状态是它那些步骤状态的函数**,按"读者最需要先知道什么"的顺序判定:失败、等人决定、受阻、
  有工作在跑、已完成。**`awaiting-human` 自成一桶,永远不算进度** —— 停在人工门上的步骤在等的是**人**,
  把它折进"进行中"会让一项研究看起来在动,而实际上它停在一个还没问过任何人的决定上。本构建叫不出名字的
  状态记为 `unknown` 并让它所在阶段受阻,而不是默认成 `not-started` —— 那会把后端已经推进的步骤报成未开始。
- **进度是数出来的,不是估出来的。** 这一行报的是:编目的总步数里过了几步、几项在等人决定、几项失败、
  几项状态未知。没有百分比,也没有完成时间:步骤之间的代价差着数量级,所以"步数的百分之多少"不是工作量的
  百分之多少,而时间会是一个这个视图无法兑现的承诺。
- **靠后的阶段说出它在等什么**,而且报的是**最早**那个未完成的阶段 —— 它才是解开链条的那一个;报靠后的
  会把读者送去还不能开始的工作。
- **"这一组由你提供"与"本构建放不下这些步骤"是两件不同的事。** 材料组是 `declared === 0`;某一组声明的
  步骤没有被投影带上来时,页面**说明这一点并列出步骤名**,而不是在宿主确实存在的步骤上渲染材料组的说明。
  默认选中的阶段由该组**声明**了什么决定,因此一个本构建放不下的投影不会落到材料组、把一个宿主自己的
  步骤答成"这是你提供的"。
- **后打开的研究不会被先打开的那个覆盖。** 每一次读取都取一个 generation,来自更早 generation 的快照被
  丢弃而不是渲染。两条 follow 写同一份状态意味着最后回答的那个生效 —— 于是会把一项研究的数字显示成另一项的。
- 这条阶段条只做导航:按下一个阶段改变屏幕上的内容,而管线无论某阶段是打开、折叠还是从未被访问,都会得出
  同一个裁断。

## 考虑过的替代方案

**把状态机搬进阶段,让步骤由阶段推导。** 读起来像是在简化,而它把权威弄反了:引擎决定什么推进了,投影
报告它,而一个能对它持有主张的分组会成为研究状态存在的第二个地方。

**显示百分比与预计完成时间。** 熟悉,而两者都是发明:管线的步骤代价极不相等,所以"40% 的步骤"不是 40%
的工作;完成时间则会是从空无中算出来的。

**按阶段字母推导分组。** 简洁,但对 D 相是错的:D 横跨三个阶段 —— 图表映射属于它所映射的结果,rebuttal
属于它所回应的交付 —— 所以前缀规则会把 rebuttal 悄悄归到写作组。

**把还没轮到的阶段藏起来。** 那样读者就看不到前面还有三个阶段、也看不到这项运行在等什么。阶段是要显示的,
靠后的那个说出它在等谁。

## 后果

- 页面不用管线词汇就能回答:正在发生什么、产出了什么、为什么停住、以及正在要求这个人做什么。
- 分组由**引擎自己的目录**机械校验:spec 直接 import 核心包的 `STEPS`,步骤一增加就会失败,所以新步骤
  不可能悄无声息地从每个阶段里消失。
- **本记录没有做的**:M05 要求的连接状态机(`idle → connecting → live → reconnecting → offline →
  resyncing → disposed`)与单一项目缓存。generation 守卫是关掉"一项研究的迟到响应不得覆盖另一项"这条
  验收的那部分;连接词汇与缓存仍未做,页面今天两者都不陈述。
