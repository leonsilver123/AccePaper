# Agent Note: 失败的检查点是运行的状态,不是驱动自己的笔记

Status: implemented

[English](2026-09-16-a-failed-checkpoint-is-the-runs-state.md) | 中文

## 问题

写不下去的检查点被驱动收进 `RunResult.checkpointErrors` —— 而一次**正在运行**的运行还没有产出那个
值。于是一项研究在推进时,读者能看到的任何东西都没有说"这些成果没有落到盘上":步骤在前进、闸门在关闭,
而这次失败唯一的记录在一个要到结束时才存在的结果里。交付记录把它当作已知限制写下了,复核则把它排在流式
进度之前:"用户可能看到研究继续推进,却不知道最新成果没有保存"。

## 决定

**这次失败记录在运行上,在报告保存的地方报告,并且拒绝就绪。**

- `ActiveRun.checkpointError` 由检查点钩子写入,**由下一次成功落盘的检查点清除** —— 所以它描述的是这次
  运行**现在**的保存状态,而不是它已经从中恢复的一次失败。钩子仍然重抛,因为驱动自己的账
  (`RunResult.checkpointErrors`) 仍是每一步保存做了什么的记录,而且运行要继续:那一步已经提交了。
- `livePersistence` 把它作为该运行持久化记录的 `error` 报出,就在**不再前进的 `revision`** 旁边。浏览器
  已经渲染这个字段,所以页面无需新增线上字段就能显示部署自己的原因。
- **就绪会拒绝。** `submissionReady = readiness.ready && checkpointFailure === undefined`,理由里点名这次
  失败。就绪是关于"材料存在且可以被再次产出"的断言;部署写不下去的材料两样都不是,而被这样告知"就绪"的
  读者会去提交一个没人能再产出一次的东西。

## 考虑过的其他方案

**留在 `RunResult` 里,让运行的结束来报告它。** 这是代码此前的做法,它输在复核点名的那一幕:最需要这条
事实的读者,正是那个正看着仍在进行的研究的人 —— 而恰恰是这个人看不到一个还不存在的结果。

**为它新增一个线上字段。** 持久化记录本来就有页面在渲染的 `error` 字段,而"这次运行的保存"是一条事实、
应该只有一个归属。为同一个失败开第二个字段,就是一份可以和第一份不一致的副本。

**检查点一失败就整体停掉这次运行。** 因为一次磁盘抖动就停掉研究,会扔掉已完成的步骤已经付过的模型调用。
那些步骤**已经提交**,失败被报告,就绪被拒绝 —— 这正是"不要发布你无法复现的东西"所需要的,而不必杀掉
一份在目录恢复后仍然可救的工作。

## 后果

- 这次失败会自我清除:下一次成功落盘的检查点会删掉它,所以一次短暂故障不会让一次运行永久未就绪。
- **审批也被它阻断了** —— 位置就在审批自己的前置条件里,在做出任何决定之前
  ([决定需要这次运行在盘上](2026-09-16-a-decision-needs-the-run-on-disk.zh.md))。本笔记当时没有阻断它,
  并指明了守卫应当落在哪里;那次改动正是落在那里。
