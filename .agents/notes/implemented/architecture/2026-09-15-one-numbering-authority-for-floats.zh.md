# Agent Note:手稿的图表编号只决定一次,并把编号交给散文

Status: implemented

[English](2026-09-15-one-numbering-authority-for-floats.md) | 中文

## 问题

导出的手稿带着**没有任何句子能指得到**的编号图注。

在真实 run 导出的包上实测:`figures/figure-1.svg` 已写出,结果表以管道表的形式进了手稿,`## Figures` 块里印着 `**Figure 1.**`、`**Figure 2.**` 与 `**Table 1.**` —— 而**没有任何一节正文**出现过 `Figure 1` 或 `Table 1`。三件事造成了这个结果,它们同一个成因:

- E1-format 用它自己的两个计数器(`figureNumber`、`tableNumber`)在遍历已渲染图表时**就地**编号。该函数之外没人知道这些数字:`figure-plan` 的读者看到的是 `totalFigures: 3` 和三条**完全不带编号**的记录。
- D3-writing 只把 `figureCount` -- 图表的**数量**、而不是**哪一个** -- 告诉散文通道。某一节根本无法指名一个图表;一个被要求引用 `Figure 2` 的写作者只能猜那是什么。
- `equationBlock` 按自己那份列表的顺序给公式编号,于是公式编号成了**第四个**独立的决定。

交叉引用是**一个事实的两种写法**:图注,和句子。把它决定在渲染图注的那一步里、而对起草那一步什么都不说,结果是第二种写法**不可能存在**,而不只是缺失。

## 决定

**由 D1-figure-map 编号,因为它就是决定"有哪些图表"的那一步。** 每条 plan 记录携带 `label`(`Figure 1`、`Table 1`)与 `title`,由 `numberFloats` 赋值 —— 一个关于 plan 数组的**纯函数**:图按 plan 顺序取 1..n,表**独立**从 1 开始。该函数不认识的 kind **拒绝**而不是跳过:未编号的图表会渲染出一个无人能指名的图注,而那正是编号存在的理由。

plan 的编号随后走两条路。

- **去散文通道。** D3-writing 把名册(带编号的图表,加上方法节要陈述的公式)作为 `context.citable` 交给写作者,并在指令里说明"引用某一项时用它**精确的**编号"。名册以**数据**形式随行,而不只是指令里的一句话:模型必须从句子里**还原**出来的编号是它可能弄错的,而论文里错的编号读起来就是在引用这份手稿**并不包含**的东西。
- **去装配器。** E1-format 用 plan 记录自带的 `label` 与 `title` 渲染每一条图注,并删掉两个计数器 —— 句子引用的编号与图注印出的编号出自**同一个决定**。到达它时**不带编号**的记录会被拒绝。

E1-format 还记录散文拿这份邀请做了什么。`crossReferences` 把可引用项分成"draft 的正文提到过的"与"没提到的",`floatsNotRendered` 则指名 plan 声明了、而这份手稿**没有**承载的图表。缺口**不靠插入句子来补**:这一步加的句子是**没有任何步骤写过**的散文,而且它会落在正好排在最后的那一节,而不是这个图表真正所在的那一节。该报告读的是 **draft 自己的**各节,而不是装配后的正文 —— 因为这一步会把公式追加进方法节,扫描装配后的文本会把每条公式**自己的标签**算成对它的引用。

## 考虑过的其他方案

**让装配器自己写引用句。** E1 知道每个图表的编号和每一节的文本,它可以在图表旁追加"as Figure 1 shows"。否决:那是没有任何步骤产出的句子,而且它附着到哪一节,这一步**判断不了**那一节是否真的在讲这个图表。`crossReferences` 让读者拿到同样的信息,而不必编造散文。

**编号留在 E1,事后把数字回传给 D3。** 不可行:D3 在 E1 之前运行,而这些编号恰恰是 D3 的请求所需要的。为它加一趟对 draft 的二次遍历,与"把决定移到拥有它的那一步"相比,复杂度不值得。

**改在 D3 里编号。** D3 是需要名册的地方,但不是决定图表的地方。一个给它**没有选择过**的图表编号的步骤,可能给一个**永远不会被渲染**的图表编上号。

**让离线 fixture 散文引用这些图表,使报告在没有模型时也不为空。** 否决:确定性散文通道写的是演示声明,没有任何研究结论,由它产出的"引用"只是流水线在演示自己的接线,而不是散文通道在引用一个图表。改为用**请求层**的 spec 钉住这份邀请;离线 run 会把每个图表都报成未被引用 —— 那正是关于一份演示草稿的**事实**。

## 后果

**fixture 草稿什么都不引用,而工件如实写明。** 离线通道的各节正文是演示声明,所以离线 run 会把每个图表与公式都列进 `crossReferences.uncited`。这是关于**草稿**的事实,不是编号的缺陷,而且它是**显式可见**的而不是靠推断。

**旧的 run 快照会在 D3 或 E1 处失败。** 本次改动之前写下的 `figure-plan` 不带 `label` 与 `title`,而这两步如今都会拒绝这样的记录。按 pre-release 立场这是允许的,但它**是一次断裂**:从旧快照恢复、D1 已完成而 D3 或 E1 未完成的 run,会带着一个具名错误停下,而不是渲染出无编号的图注。

**公式可被引用,但不经过起草。** `MODEL_EQUATIONS` 是模块常量,所以 D3 在方法节存在之前就知道它的编号。散文通道被提供这些编号;由 E1 渲染它们;它们如何被陈述这一点没有任何别的变化。
