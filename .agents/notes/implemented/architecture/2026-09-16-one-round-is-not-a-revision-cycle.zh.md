# Agent Note: 一轮不是一条修订循环

Status: implemented

[English](2026-09-16-one-round-is-not-a-revision-cycle.md) | 中文

## Problem

`D4-rebuttal` 只跑一次。它的 `roundId` 是字面量 `t19s-rebuttal-1`,而当应用器拒绝一份补丁时 —— 针对另一个版本写的、用相同文本替换正文、或与同一节的另一份补丁冲突 —— 那条意见就留在那里,没有东西 可以再试。

应用器本身是谨慎的:它把每份补丁绑到写作时针对的版本上,宁可拒绝也不静默丢掉中间发生的一切。缺的是 一条循环的另一半。**拒绝是信息**,而没有任何东西依据它行动。

检查单说得直白:「D4 只有应用器,没有可持续闭环 … 轮次和预算均有限,未解决转人工」。

## Decision

`D4-rebuttal` 的模型路径是一条**有界循环**:

- 每一轮都被告知上一轮留下的是**哪些节**,并拿到**当前这份**手稿,于是它的补丁是针对当前正文写的;
- 上限是 `revisionRounds` —— **部署配置**,经 `stepTimeoutMs` 走的同一条路从研究引擎自己的 config 读入,executor 里默认 2;
- 工件带上 `rounds`、`revisionRounds` 与 `stoppedBecause`(`closed` / `no-progress` / `budget`), 于是一个读者能看出作者被问了一次,还是被问了配置允许的那么多次。

**「无进展」按节测量,不按 issue id。** 每一轮都从 1 开始编号,于是 `d4-issue-1` 在每一轮指的是不同 的意见;比较 id 会把两轮在**同样几节**上失败叫作**有进展**,然后把预算花在重复提问上。轮次记录同时 带上两者:`open`(issue id,用来在 `issues` 里找到它们)与 `openSections`(下一轮被告知的东西)。

`no-progress` 会提前停下:第二轮留下的仍然是完全相同的那些节,说明问题已经问过了,第三次提问只会花 预算、什么也学不到。

## Alternatives considered

**一直重试到全部关闭。** 拒绝:一个不肯关闭某条意见的模型,第四次问也不会关闭,而上限正是让一次运行 的成本可预期的东西。

**按 id 比较未关闭的意见。** 拒绝,理由同上 —— id 是位置性的,跨轮什么也测不出来。那是第一版实现, 被一条测试抓住了。

**还有意见未关闭时让 `D4-rebuttal` 失败。** 拒绝:一轮关闭了它提出的大部分就是一轮能工作的修订,而 让该步失败会丢掉它确实应用了的补丁。错的是声称**这次运行**完成了 —— 那由就绪判定来裁。

**预算耗尽时转成一道人工门。** 没有做。该步留在 `stoppedBecause: 'budget'` 与它那些未关闭的意见上, 而就绪判定带着这些意见拒绝这次运行。一道人能放行的人工门会是同一个事实的第二套机制;而「必须有人来 决定」在这里的诚实版本是:运行不就绪,并说出为什么。

## Consequences

- `tests/d4-model-revision.spec.ts` 在模型路径上驱动整条循环:第一轮的 Method 补丁用 D3 已经写过的 文本替换正文而被拒,第二轮被问起并关闭它,`rounds` 两条都点名,`stoppedBecause` 是 `closed`,而在 有人批准之后这次运行**变为就绪**。第二条测试钉住卡住的情形:同一份回复两次,停在 `no-progress`, 意见仍然开着,就绪仍然是 false。
- 第三条测试钉住上限属于部署:`revisionRounds: 1` 产生一轮,`stoppedBecause` 是 `budget`。
- `docs/config-catalog.md` 带上新字段,而引擎在值进入的地方就拒绝小于 1 的上限,而不是在它本该中止的 那一步。
