# Agent Note: 研究比启动它的页面活得久

Status: implemented

[English](2026-09-17-a-study-outlives-the-page.md) | 中文

## 问题

部署为一项研究发放过的唯一凭据是 run id,而页面把它留在自己的存储里。关于一次运行的其他一切都在盘上 —— 快照、工件、闸门裁断 —— 所以关掉标签页、刷新,或者在另一台机器上打开这个应用的人,面对的是一个装满已完成与未完成研究的部署,却无法命名其中任何一个。运行控件会说"本会话没有跑过任何东西",这对会话是真的,对部署是假的。

断线恢复要过的验收需要的就是这同一次读取:正在被驱动的研究在刷新之后仍被找到;服务重启后打开的页面把这项研究显示为**中断**,而不是不存在。两者都无法由页面记住的东西回答,因为一个全新的页面什么都没记住。

## 决定

**部署回答它持有哪些研究,工作台把它们作为一份可挑选的列表提供出来。**

- `@Remote('listRuns')` 为每项研究返回一条记录,最新的在前。记录带着 id、执行状态、项目版本、管线编目的步数里过了几步、这次运行是否可提交,以及人需要据以行动的两条失败事实:最后一次保存为什么没落盘,驱动为什么停下。
- **本进程持有的运行从**它的活状态**报告;本进程不持有的运行从它的**文件**报告为 `stopped`。** 同一项研究即使在两处都存在也只出现一次,因为活状态就是它自己的读者看到的那个状态。`stopped` 只说明**本进程**没有东西在驱动它 —— 记录里还带着快照被取走时正在飞行中的步骤,这才让一项中断的研究与一项跑完的研究分得开。
- **顺序是 id 的顺序,不是版本的顺序。** 版本数的是**一项**研究提交了什么,无法把两项研究相互排序;目录列举的顺序属于文件系统。id 是 UUID,所以按 id 排序在多次调用、多个进程之间都稳定。
- **读不到的列表会被报出来,而不是渲染成"没有研究"。** 客户端带着后端自己的原因拒绝,读者看得到。"这个部署没有任何研究"与"我问不出来"有不同的补救办法,而其中一个不是"你的工作没了"。
- 只有当宿主**既能列举也能打开**研究时,选择器才出现;打开走的是运行控件同一条 follow,并记住 id,所以刷新会落回同一项研究。

## 考虑过的替代方案

**把 run id 从 session storage 改存 `localStorage`。** 最省事的修补,而它回答的是另一个问题:活得比标签页久的凭据会在**下一次**访问时回来,一项一天前的运行会被打开、被报成 `stopped`,报给一个并非为它回来的读者。记住"本次访问在看什么"是会话事实;找到一项研究是部署读取。

**在后端维护按浏览器区分的"最近研究"列表。** 这让部署去记住哪个浏览器启动了什么,而部署没有理由知道这件事;对**没有**启动过它的浏览器,它仍然什么都显示不出来 —— 而验收说的正是这种情形。

**页面空着时自动打开最新的一项研究。** 这会让一个为别的事而来的读者待在一项他没有选过的研究里,并且把一张空页面变成一个关于"哪项研究更重要"的主张。列表陈述存在什么,由读者来挑。

**只从快照目录列举推导。** 它恰好漏掉人最可能在找的那项研究:本进程正在驱动的运行还没有自己的快照目录。

## 后果

- 研究可以被一个对它一无所知的浏览器找到,这正是刷新、关页重开、服务重启三项验收需要的东西。
- 页面获得了它的第一次**与它已经能命名的运行无关**的读取,以及它的第一个"缺席本身有意义"的控件:不能列举研究的宿主显示的是**没有选择器**,而不是一个空的选择器。
- **新增一个 `@Remote` 方法必须同时就位四处,而最后一个是构建产物。** 方法要在源码、宿主的生成注册表、本包的 `lib/` 里,还要在浏览器实际调用的那个 Remote assembly bundle(`dsh-api-remotes/lib/client.js`)里 —— 它把各包生成的描述符**内联**进来。若打包发生在生成器重写描述符之前,页面就少一个方法,而页面会把它报成 `listRuns is not a function`:读起来像挂载或缓存的问题,其实两个都不是。浏览器验收探针现在会拒绝在缺少它所调用方法的 assembly 上运行。
- **这件事不做什么**:它列举研究,而对"某个人当时正在看哪一项"一言不发。恢复那件事仍然是页面自己记住的凭据,本记录不改变它。
