# Agent Note: 包会说明自己是哪一个,而最终包是可以被拒绝的

Status: implemented

[English](2026-09-17-a-package-says-which-one-it-is.md) | 中文

## 问题

导出只写一种包。它什么都不拒绝,而它的 manifest 把就绪事实当作数据带着:`submissionReady: false`、
`profileEligible: false`、`E2-submit: gated`。一个停在 A1 的运行的包、一个在 evaluation profile 下做的运行的包、
以及一个人批准过的运行的包,写出来一模一样,只有逐字段比对 manifest 的读者才能把它们与"已经完成的那一份"分开。

最要紧的那一个,是**导出发生在什么时候**造成的。它在驱动结束时导出 —— 而到达人工门的运行,按构造就停在那里。
于是交付那篇论文的 manifest 记着 `E2-submit: gated` 与 `submissionReady: false`,而运行本身在那个人于页面上批准之后
记的是 `E2 → passed`。那次批准从未到达这份文件。页面若把那份文件当作最终包提供,提供的就是决定之前的那个状态 ——
这条发现当时被写进了交付自己的索引里,编号 C09,没有修。

## 决定

**包会说明自己是最终包还是工作草稿,而最终包是一个带着自己守卫的操作。** 九个条件,从运行自己的记录里算出,
而不是来自调用者说的任何话:

`production-evidence`(运行在 production profile 下进行)、`manuscript-produced`、`every-step-closed`、
`no-refused-sections`、`no-open-issues`、`approval-recorded`(人工门上有一条 `approved` 决定)、
`approval-current`(那条决定仍然覆盖运行当前持有的产物版本)、`required-files-present`(运行自己的稿件声明的每个
文件)、`run-saved`(运行最后一次写入已落盘)。

- **manifest 带着它们**:`state`(九个全部成立才是 `final`)、这些检查本身与它们各自观察到的内容,以及 `approval`
  —— 谁决定的、什么时候、事件 id、以及决定当时所依据的产物版本。比对两个包的读者能看出批准的是不是同一个版本。
- **驱动结束时导出的那一份是草稿**,并且在自己的 manifest、自己的检查、以及自己的 `run-summary.md` 里都这么说。
  停在人工门上的运行还没有被决定,所以它的包不是最终包 —— 这让 C09 那处不一致**不可能发生**,而不只是被记录下来。
- **`@Remote('exportRunPackage')` 按需写包**,可选 `draft` 或 `final`。`final` 在操作里被拒绝,点名第一条不成立的
  条件,而且**在写任何东西之前**:一个在退出路上清空目录的拒绝,会连读者手上的草稿一起拿走。`draft` 照写并带标注 ——
  想要当前材料的人应该拿到它,而不是一个对谁都没帮助的拒绝。
- **页面陈述宿主的答案,自己什么都不算**:它渲染 `state`、每一条带宿主原话的检查,以及两个控件。宿主没有说状态时
  页面什么都不说,因为在一个从没这么说的宿主上把包显示成最终包,正是这个字段存在的理由。

## 考虑过的替代方案

**在运行就绪之前拒绝导出任何东西。** 在闸门上索取当前材料正是最常见的情形 —— 那恰恰是人想看的时候 —— 拒绝会让他们
什么都读不到。草稿照写,并且其中每个文件都说明自己是什么。

**让页面判断一个包是不是最终包。** 这些事实属于运行:它的步骤状态、它的登记表、它的批准记录、它最后一次写入。
由页面来算是就绪的第二份实现,而两者分歧的时刻恰恰是最要紧的时刻 —— 正是这个代码库反复付出代价的那种失败。

**决定落地时自动重新导出。** 那会让审批路径必须知道包目录,而一次在无人看着时作出的批准会写出没人要过的文件。
索取最终包是一个有作者的动作,而操作通过写下文件记下了是谁要的。

## 后果

- **C09 按构造闭合**:读者在批准之后拿到的那一份,就是他们索取的那一份,它的 manifest 写着 `final` 与让它成为最终包的
  那条批准。驱动结束时写下的草稿仍然可读,且不可能被误认成它。
- **拒绝在作出决定的那一处强制执行**,所以从没见过页面的调用者会因为同样的理由被拒绝 —— 页面上的控件在不在、藏没藏,
  都不改变任何事。
- **未验证**:没有"包达到 `final`"的浏览器读数,因为一个 `final` 包需要一次 production profile 下、人工门被人批准过的
  运行,而用来做浏览器读数的部署是 evaluation 的。拒绝与草稿有浏览器读数;`final` 这条路径由检查的单元用例与操作
  自身的拒绝用例覆盖。
