# Agent Note: 每一次写入都以「上一次真正落盘的写入」所推进的版本为基准

Status: implemented

[English](2026-09-17-every-write-is-based-on-the-last-landed-write.md) | 中文

## 问题

修订闭环一步一步地工作着,而三处缺陷躲过了它当时拥有的全部测试:960 项研究层测试、接受的各种拒绝用例、面板的
jsdom spec,以及恢复探针。每一处都长在**两个各自正确的部分之间**,而且每一处都只有把整个闭环从浏览器对着一个真实
部署走一遍才会暴露。

1. **候选稿写在 id `''` 之下。** `generateCandidate` 从调用者手里取 `request.candidateId`,而页面在请求写一份候选稿
   时**没有**候选稿可以命名 —— 它送的是空字符串。于是每个请求的每份候选稿共用一个 id:每个请求一个
   `candidate-.json`,第二份候选稿覆盖第一份,`review-.json` 指的是最后被复核的那一份,而页面上复核与接受控件全都
   指着同一个候选稿。线上的类型文档早就写明了该发生什么 —— "写一份候选稿时该字段被忽略,id 由它自己铸" —— 所以这处
   缺陷是**实现与自己声明的契约不一致**,而这类不一致没有任何类型会拦下。

2. **接受的落盘基准取错了计数器。** 快照存储的比较并交换比较的是**快照版本**:一个每次保存都会推进的写入计数,
   检查点也算。而接受的写入以运行的 `projectRevision` 为基准 —— 那是"这项研究提交了什么"的计数,检查点写文件时它
   不动。任何被检查点写过的运行都会让两个计数器拉开,而被**取回**的运行一开始就拉得更开。结果:接受被记录了、它的
   `persisted` 带着存储给的原因报成 false,而它发布的稿件从未进到文件里 —— 页面显示着一份已被接受的稿件,而重启会
   显示 E1 那一份。

3. **写入不给自己记账。** `persistRun` 推进了文件却谁也不告诉,于是本进程**下一次**写入的基准差了一版 —— 第 2 条
   正是这样被触发的:审批写了这次运行,紧随其后的接受被拒,"the persisted snapshot is at revision 25 but this write
   is based on revision 24"。

## 决定

- **候选稿的 id 由部署铸造。** `generateCandidate` 不读调用者的那个字段,而 `buildCandidate` 在没拿到 id 时自己铸一个。
  此后每一次读取都走这个 id:记录文件以它命名、复核按它查找、接受要命名它、页面的每个控件都钉在它上面。
- **每一次写入都以 `active.savedRevision` 为基准** —— 每次真正落盘的写入都会更新这个字段。`persistRun` 把自己的结果
  (成功或失败)记进去,检查点的回调把它写出的版本记进去,取回存量运行时用读到的那份快照为它赋初值。
- **读的是这个字段,不是"上一次写入的记录"。** 记录描述的是一条路径的写入:检查点推进文件时不经过 `persistRun`,
  所以从那条记录读出来的基准对另一条路径一无所知。

## 考虑过的替代方案

**继续照抄调用者的 `candidateId`,让页面自己铸一个。** 那就等于让页面为一条它并不拥有的记录发明 id,而两个标签页同时
请求会为同一个请求的两份候选稿铸出两个 id —— 正是这个 id 存在所要防的事。铸造属于写记录的那一处。

**以项目版本为基准,并放宽存储的守卫。** 守卫是防止两个写入者悄悄替换彼此状态的东西,而且一个报错计数器的写入,
下一次检查点跑过之后照样会被拒。错的是计数器,不是守卫。

**每次写入前都读一遍快照文件拿一个新鲜基准。** 这正是 `retryRunSave` 有意为之的做法,对**重试**是对的:它与磁盘对账,
而不是相信一个记住的数字。对一次普通写入,它会让运行自己的决定与一个外部写入者去抢一个本进程**已经知道**的版本 ——
而进程之所以知道,正因为它就是写入的那一方。

## 后果

- id 那处由铸造它的模块里的单元用例守住(去掉铸造,该用例失败)。另外两处由浏览器探针守住:接受分支从磁盘把稿件读
  回来,读到 `version 2 / producer human-acceptance` —— 正是修复前失败的那条读数。
- **有两件事仍未验证,照实记录**:没有 spec 覆盖接受的服务侧接线(要一份"到达闸门且已有稿件"的夹具,而离线路线产不
  出来);也没有"由**模型**写出的候选稿通过复核"的读数 —— 闭环是用部署自己的确定性写作者驱动的,那份文本自己标注了
  这一点。
- **由此暴露、但未修的一条产品事实**:`numbers` 检查是**单向的**。它拒绝"运行没测过的数字",却不要求运行持有的数字在
  修订后活下来,于是一份把某章节全部测量值删掉的候选稿能通过全部三项检查。更严的规则需要它自己的单元与用例。
