# @deepseek-ai/dsh-research-web

[English](README.md) | 中文

科研工作台的双面插件。host 半边刻意惰性(不做任何宿主注册),浏览器半边把 `conversation.view` slot 的 `research` 标签页挂载为 9 个面板:综述 / 流水线 / 图 / 表 / 路线图 / 闸门 / 对抗 / 审批 / 恢复。

面板由 `panels.ts` 的纯 selector 从一份 run summary 派生,`summary.ts` 是无依赖的视图模型,因此两者无需 Cordis 即可单测。文案经 `client/locales.ts` 的 `zh` / `en` 字典,符合客户端的本地化归属约定。

## 已知限制与延期工作

- **页面跟随运行的流,而不是轮询它** (2026-09-16):`client/follow-source.ts` 打开 `followRun`,渲染每一帧 `snapshot`(服务自己的投影),并把 `event` 帧当作**位置**使用:接不上它所持序号的帧会被拒绝,页面选择重开,而不是应用一个它无法交代的状态。收到 `resync` 帧时,页面**不带**那个被拒的 cursor 重开;位置会跨重开保留,所以重开能判断自己是否漏过东西。重开次数有上界(`MAX_FOLLOW_ATTEMPTS`),因为一个对每次打开都回以拒绝的宿主会让标签页空转。**这里不把事件重放进投影** —— 那份投影属于服务,客户端里的第二份可能与它不一致,而看上去完全合理。
- **页面启动运行并跟随它,而不是等它跑完** (2026-09-16):`client/index.ts` 现在先调 `startRun` 拿到运行 id,再读 `runSnapshot`,每读到一份快照就交给工作台 —— 所以研究还在进行时页面就已经显示这次运行,并在就绪徽章旁标出运行 id 与执行状态(`running` / `stopped` / `failed`,执行器抛异常时带上它自己的错误)。在此之前它等待 `remote.research.run(...)`,那个调用要等整项研究结束才 resolve:几分钟的白屏,以及一次刷新就丢掉的运行身份。**命令 id 每次按下时生成,重试时复用**,所以页面没读到的响应不会变成第二项研究。**刷新会恢复这个标签页此前跟随的那次运行**,凭据是会话级的句柄:执行器是宿主的,所以刷新可能丢掉的只是页面手里的把手,而一个回来就说"本次会话还没有运行过"、压在一项仍在进行的研究上的页面,等于把自己的失忆报成了运行的状态。**服务没有任何记录的那次运行会如实说明**,而不是去轮询一个不存在的运行。**这不是事件流**:页面按客户端固定间隔轮询,所以步骤的进展在一个间隔内出现,而不是落地的当下;也没有 cursor、去重或补缺 —— 那些随需要它们的通道一起来。**宿主没有给出时 `summary.execution` 为 null**,页面此时什么都不说,而不会默认为已停止。
- **没有通过的步骤在它自己那一行说明原因**(2026-09-16):概览的步骤列表过去只写 `blocked`,而原因藏在另一个页签里的一条门禁记录中 —— 读者得先知道要去找它。现在每一步都带上它那条未通过门禁的理由(聚合自己写的那句话),于是一个因为必需检查从未运行而被扣住的步骤,**原话说出这件事**。**仍然不做的**:它不说该怎么办。理由点名了检查;补救仍然是读者的事。
- **重试就是同一条命令**(2026-09-16):审批面板为每个意图生成一个 `commandId`,并在读者失败后再按同一个按钮时**复用它** —— 一次超时不能变成第二次决定。改主意投相反的一票会生成一个新的,因为那是另一个意图。这个 id 在 wire 上是必填的:一条没有身份的命令无法被安全地重试。
- **页面说出这是一次什么样的运行、以及有没有东西就绪**(2026-09-16):wire 孪生现在声明后端自就绪拆分落地以来就带着的四件事 —— `evidenceProfile`、`profileEligible`、`submissionReady`、`readinessNote` —— 而工作台把模式与就绪标在来源徽标旁边。**孪生此前没有声明它们**,于是浏览器四条全收到了、却一条也叫不出名字:与 `packageExport`、`runPersistence` 被注释标注过的是同一种漂移,也是这一面第三次静默丢掉主机字段。就绪标在徽标所在的地方,**不藏在页签后面**,因为它对整个运行都成立。**未说明的就绪渲染成"未说明"**,既不是就绪、也不是失败:`null` 与 `false` 是两个不同的答案,而只有其中一个是查过的。
- **停在人工门的运行说它在等,不说它完成了**(2026-09-16):当每一个可自动完成的步骤都已关闭、而某一步是 `gated` 时,`runStatusOf` 返回新的 `awaiting-approval`,而不是 `completed`。**被 gate 住的步骤不是没做完的步骤** —— 流水线正是停在它该停的地方 —— 而一个在需要读者的那一刻写着「已完成」的页头,正是这个状态存在的意义所要阻止的承诺。引导文案在同一次改动里更正:走完十六步产出的是**材料齐备**的手稿,而「材料齐备不等于可投稿」现在说清了还差什么(生产证据模式、全部门禁关闭、没有未关闭的评审意见、一次人工批准)。
- **页面说出它显示的是哪个项目版本**(2026-09-16):Remote 投影带上运行的 `projectRevision`,工作台把它标在来源徽标旁边,于是一个读者能分辨屏幕上的东西与一个导出的包(它的 manifest 带同一个数)说的是这份研究的同一个状态,还是两个。**主机没说就不显示**:缺失的版本不会被渲染成 0 —— 0 是一次运行真实会处在的版本,显示它等于点名一个没人读过的状态。**还不是逐个产物的**:wire 上的产物清单没有带各自的版本。
- **后端已应用的决定就显示为已应用,不管别的东西失败成什么样**(2026-09-16):审批回执现在带 `approvalEventId`、`decidedAt` 与 `persisted`,而面板把三件独立的事实分别说出来,过去它只说一件。一个没有落盘的决定会**说出这件事** ——「决定已生效,但保存失败 —— 重启后它会丢失」—— 而不是读起来与落盘的那个一模一样;而一次客户端读不回来的运行会说「决定已生效,但页面未能刷新」,而不是被报成 MALFORMED RESPONSE、告诉操作者审批失败、而后端说它通过了。**在这之前,客户端把 `persisted` 与 `persistenceError` 扔在地上**,而一次构建摘要的失败会用 `ok: false` 覆盖掉一个成功的决定。这三个回执字段在 wire 上是**必填**的:早于它们的后端会被报成 host/client 构建不匹配,而不是被默认填充 —— 默认填充等于把这套通道存在的理由本身(那两件事实)编出来。
- **真实数据通路已接**:工作台经 `ctx.remote.research.run({})` 启动一次真实运行并渲染它,徽标跟随数据来源。**它不造假 run**:本次会话没跑过时,只显示引导区与运行控件;运行失败时说明原因,屏幕上不留任何 run。原先回落到的那份演示 run 已从 `src/` 移出 —— 现在在 `tests/support/` 下,生产代码 import 不到。
- 组件**有注入缝**:`ResearchWorkbench` 接受 `summary`、`onRun`、`onPropose`、`onApprove`(注入摘要、启动并跟随运行、向宿主索取研究方向、提交人工裁决)。`onRun` 接收已确认的方案,以及一个用来回报每一份快照的回调,所以进行中的运行会随进展被渲染。`summary` 缺席即"没有跑过",视图如实这么说,而不是补一份进去。
- **人工审批已接通后端**(2026-09-14):`client/approval-source.ts` 经 `ctx.connection.rpc.call('/research-approval', 'decide', ...)` 把裁决送到 `dsh-research-team` 注册的、由宿主做浏览器认证的通道上,面板只渲染后端回传的状态、attempt 与操作者;驳回/失效/传输失败**如实报错**并让该步留在待审。`onApprove` 缺席时(部署没有浏览器认证通道)两个按钮**禁用**并说明原因,而不是显示一个没人做过的决定。
- 恢复面板**只读,并写明原因**:本部署没有开放"从快照恢复"的入口,所以这一页只报当前屏幕上的 run,不提供任何动作。它此前有一个"从快照恢复"按钮,处理函数加载的是那份演示 run —— 看起来像恢复,实际是把读者正在看的 run 换成了编造的数据。
- **测试覆盖已补齐**(B5):9 个标签页全部被点击,`panels.ts` 的 selector 全部被 import;`src/index.ts` 的 host 半边是刻意的空体(视图由 client 半边挂载),因此无测试引用它。

不发布不变式伴生入口,因为本包不发布任何运行时不变式条目:它的宿主半边刻意惰性,没有可发布的伴生对象。

- **闸门提供了评审者真正想说的第三件事**(2026-09-17):审批面板把 `request_changes` 连同人写下的要求一起送出,而那个按钮在有文字之前保持禁用 —— 后端拒绝什么都没写的请求。**回执陈述的是后端记录的决定**,不是从步骤状态推导出来的值:修改请求让步骤保持 `gated`,所以推导出来的值会把操作者没做过的驳回报给他,并把他写下的要求藏起来。面板把三个决定都陈述出来,而快照里带着已记录决定的步骤会显示它 —— 谁决定的、什么时候、要求了什么 —— 因此刷新过的、或从未打开过的页面,是从这次运行上读到那条要求,而不是从某个聊天里。
- **工作台按研究者的任务组织,而不是按管线词汇**(2026-09-17):六个阶段(`stages.ts`)把这次运行**自己的**步骤分组 —— 研究任务与材料、文献与研究定位、方法与实验准备、实验结果与图表、论文组织与写作、审阅修改与交付 —— 而每个阶段显示的状态都从它那些步骤的状态推导,所以折叠某个阶段或访问某个阶段都不会改变研究是否推进。材料组不报告任何步骤:一项研究存在之前人提供的东西不是第十七个被执行的步骤。**`awaiting-human` 自成一桶,永远不算进度**;本构建叫不出名字的状态记为 `unknown` 并让其阶段受阻,而不是默认成 `not-started`。进度行报的是计数 —— 编目总步数里过了几步、几项在等人决定、几项失败、几项状态未知 —— 而且**没有百分比、没有完成时间**。靠后的阶段报出它等待的**最早**那个未完成阶段。**"这一组由你提供"与"本构建放不下这些步骤"是两件不同的事**:材料组是 `declared === 0`,而某一组声明的步骤没被投影带上来时,它说明这一点并列出步骤名。**后打开的研究不会被先打开的那个覆盖**:每次读取取一个 generation,来自更早 generation 的快照被丢弃。分组由 `tests/stages.spec.ts` 对着**引擎自己的目录**校验:它直接 import 核心包的 `STEPS`,步骤一增加就会失败。**未做**:M05 要求的连接状态机与单一项目缓存。
- **部署持有的研究以列表提供,所以一个什么都没记住的页面也能打开其中一项** (2026-09-17):工作台渲染 `[data-research-projects]` 行 —— 每项研究一行,带着管线编目的步数里过了几步、执行状态、后端自己报出的 `saveFailure` 与中断事实、用来打开它的 run id,以及一个「打开这项研究」按钮。列表在挂载时从部署读出,而选择器**只在**宿主同时提供 `onListRuns` 与 `onOpenRun` 时出现;不能列举研究的宿主显示的是没有选择器,而不是一个空的选择器。**读不到的列表报成失败,不渲染成「没有研究」** —— 「这个部署没有任何研究」与「问不出来」有不同的补救办法 —— 而 `runListFrom` 把本构建叫不出名字的执行状态映射为 `null`,不折进 `stopped`。打开一项研究走的是运行控件同一条 follow,并记住 id,所以刷新会落回读者选中的那项研究。
- **运行接线已是 Runtime-verified**(2026-09-15)。研究标签页启动真实运行 —— `ctx.remote.research.run({})` → `run-source.ts` 映射 → `ResearchWorkbench` 渲染 —— 并已被一个独立浏览器探针对着运行中的 Host(1120 端口)驱动过,断言对着后端自己的记录(`.workbuddy/tmp/verify-browser-b.mjs`,30/30)。这里此前写"没有任何浏览器驱动过",写下时是真的,现在不再是。
- **审批面板同样只是 Integration-verified**:它的提交器由 jsdom spec 对着一个 mock 的 Connection 服务覆盖,`dsh-research-team/tests/approval.spec.ts` 覆盖后端核对与 §8.1 各条不变量;真实 socket 上验过的是**通道本身**(无 cookie → 401 且处理器不被调用,令牌换 cookie → 200 并写入后端记录,伪造 cookie → 401),不是浏览器里的这一次点击。
- **`summary` 的载荷形状是本包声明的结构孪生**。服务在 Host 面编译、本包在 Client 面,而客户端 bundle 不取跨插件值依赖,所以 `run-source.ts` 里的 `WireRunSnapshot` 是**复述**而不是导入。两边字段名不一致会让视图静默变空。Host 侧的集成 spec 断言的正是同一组字段名。
- **MOCK 徽标跟随数据来源**(`summary.isMock`),而且已**没有任何生产路径**会产出 fixture 来源的摘要:`run-source.ts` 映射出来的 run 一律标 `live`。因此该徽标只对"注入一份 fixture 摘要的宿主"可达,今天就是那些 spec。
